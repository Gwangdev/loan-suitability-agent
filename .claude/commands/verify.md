# 검증 — 1회

## 내장 리뷰 커맨드와의 분담 (필수 확인)

`/code-review`·`/security-review`는 Claude Code 내장 커맨드다. **이 커맨드가 대체하지 않는다** — 정보원이 다르기 때문이다. `/verify`는 명세·증거·상태를 보고, 내장 커맨드는 **diff의 코드 라인 자체**를 본다. 같은 것을 두 번 보는 게 아니라 서로 못 보는 자리를 본다.

그래서 금지가 아니라 **자리를 고정한다.** 정의되지 않은 채로 두면 항목마다 돌게 되고, 바뀌지 않은 코드를 다시 읽는 데서는 새 정보가 나오지 않는다. 그게 실제 낭비다.

| 커맨드 | 보는 것 | 자리 | 횟수 |
|---|---|---|---|
| `gate.py` | 기계로 셀 수 있는 것 (축 H·S·A·L·X·V…) | `/build` 첫 항목, 체크포인트 | 제한 없음 (비용이 없다) |
| `/code-review` | diff의 정확성 버그·중복·단순화 | **체크포인트, 커밋 직전** | 커밋 범위당 1회 |
| `/security-review` | 논리 수준 보안 — 권한 우회, 신뢰 경계, 입력 경로 | **외부 표면이 추가·변경된 체크포인트만** | 해당 커밋 범위당 1회 |
| `/verify` | 명세↔산출물↔증거, 규제, 설계 정합성 | 개발 완료 후, 격리 컨텍스트 | 전체 1회 |

**하지 않는 것**
- `/build` 반복 구간에서 항목마다 리뷰 커맨드를 돌리지 않는다. 관례는 첫 항목에서 굳는다.
- 같은 커밋 범위에 같은 커맨드를 두 번 돌리지 않는다. 지적을 고친 뒤 재검토가 필요하면 **고친 범위만** 대상으로 한다.
- 내부 리팩터링만 있는 커밋에 `/security-review`를 돌리지 않는다. 축 X가 이미 기계로 돌아 있고, 신뢰 경계가 바뀌지 않았으면 볼 것이 없다.

**축 X와 `/security-review`의 관계.** 축 X는 형식으로 증명되는 것(박힌 자격증명, 알려진 취약 패턴)을 예외 없이 잡는다. `/security-review`는 그것으로 잡히지 않는 것 — 이 요청자가 이 자원에 접근할 권한이 있는가 — 을 본다. **X가 통과했다는 사실이 후자를 보장하지 않는다.**

## 실행

개발 주체의 자기보고를 신뢰하지 않는다. **`independent-verifier` 서브에이전트**를 호출해 격리된 컨텍스트에서 검증한다.

서브에이전트에는 `PROJECT_STATE.md`·`PROJECT_LOG.md`·`SPEC.yaml`과 산출물만 전달한다. **개발 대화 맥락을 주입하지 않는다** — 주입하면 독립성이 사라지고 같은 오류를 함께 확증한다.

검증 항목은 `.claude/agents/independent-verifier.md`에 있다. 이 커맨드에서 다시 나열하지 않는다.

## 지적을 코드 주석에 남기기 (필수)

지적을 수정할 때 기록만으로 끝내지 않는다. **고친 자리에 왜 고쳤는지를 남긴다.** 고친 직후에 쓴다.

**태그·번호를 쓰지 않는다.** 코드는 제출물이고, 하네스 작업용 표기는 제3자에게 의미가 없다. 게이트 `L2`가 BLOCK한다.

원인 → 과정 → 결론이 드러나게 자연어로 쓴다.

```java
// 조회 후 삭제하는 구조였으나 두 시점 사이에 참조가 삽입될 수 있었다.
// 선행 검사로는 막을 수 없어, DB 제약 위반을 잡아 도메인 예외로 변환하는 방식으로 바꿨다.
```

과거 상태 / 무엇이 틀렸나 / 어떻게 바꿨나 — 세 요소가 다 있어야 한다. 저장소를 처음 보는 사람이 읽는다고 가정한다.

**대응 관계는 대장이 갖는다.** `PROJECT_LOG.md` 피드백 대장에 지적별로 `커밋 해시`·`파일:라인`을 적는다. 코드에 번호를 심지 않는다. 지적 하나당 회귀 테스트 하나를 만들고, 지적 내용이 테스트 이름에 남게 한다.

## 완료 점검

- 검증 결과 전문은 `PROJECT_LOG.md`에, 판정값·시각은 `PROJECT_STATE.md`의 「완료 판정」에 쓴다:
  `완료 / 개발 중 / 검증 필요 / 조건부 완료 / 배포 보류 / 사용자 결정 필요`
- 지적은 `PROJECT_LOG.md` 피드백 대장에 등록하고(커밋 해시·파일:라인 포함), 미조치 건만 `PROJECT_STATE.md`에 요약한다
- 사용자에게 보고한다: **지적 N건 / 회귀 테스트 K건 / 대장에 커밋 해시가 기록된 건수 M건.** N과 M이 벌어지면 대응 기록이 누락된 것이다
- 버전+1
