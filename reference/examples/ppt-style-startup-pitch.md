# PPT 스타일 가이드 예시 — 스타트업 피치

> 사용법: 이 파일을 `reference/ppt-style.md`로 복사해 사용하거나, `/handoff ppt reference/examples/ppt-style-startup-pitch.md`로 직접 지정한다.
> 이 가이드는 `SKALA_Code_Review_Lab_Manager_Briefing_Startup_Backup.pptx`에서 사용한 시각 체계를 일반화한 것이다. 특정 프로젝트의 문구나 고유명사는 복제하지 않고 디자인 원칙만 재사용한다.

## 역할
전문 프레젠테이션 디자이너로서 의사결정권자가 핵심 주장과 요청사항을 빠르게 파악할 수 있는 스타트업 피치형 슬라이드를 설계한다.

## 청중·목적
- 발표 대상: 실무 매니저, 의사결정권자, 초기 투자자 또는 프로젝트 승인권자
- 발표 시간: 미지정
- 발표 목적: 제안의 핵심과 판단이 필요한 사안을 앞에 제시하고, 서비스 개요·작동 방식·기대효과·실행 조건을 거쳐 마지막에 결론을 다시 확인한다.

## 톤·어조
- 스타일: 스타트업 피치, 카테고리: 비즈니스
- 본문은 명사형 종결과 개조식 문체를 기본으로 사용한다.
- `~합니다`, `~입니다`, `~했습니다` 같은 서술형 종결어미를 반복하지 않는다.
- `검토 필요`, `오류 발생`, `적용 예정`, `사용 제한`, `구축 완료`처럼 핵심 명사나 상태로 짧게 끝낸다.
- 발표자가 말로 보충할 내용까지 슬라이드에 완전한 문장으로 적지 않는다.
- 추상적인 슬로건보다 구체적인 주장, 질문, 행동을 사용한다.
- 자료의 목적이 승인 요청이면 서비스 홍보보다 판단 항목을 우선한다.
- 승인권자의 답변이 필요한 문구는 예외적으로 짧은 의문형 사용을 허용한다.

## 분량·구성
- 권장 슬라이드 수: 8~12장
- 권장 흐름: 표지 → 핵심 제안 → 판단 요청 → 서비스 구조 → 사용자 경험 → 차별점 → 실행 기반 → 기대효과 → 운영 조건 → 결론
- 각 슬라이드는 하나의 주장만 전달한다.
- 첫 3장 안에 “무엇을 만들려는지”와 “무엇을 판단받아야 하는지”가 모두 등장해야 한다.

## 디자인·시각 방향

**컬러 시스템**
| 용도 | 색상 | 사용 원칙 |
|---|---|---|
| 배경 | `#FFFFFF` | 전체 슬라이드의 기본 배경 |
| 기본 텍스트 | `#111111` | 제목과 핵심 본문 |
| 강조 | `#6366F1` | 핵심 숫자, 단계, 링크, 짧은 강조선 |
| 보조 텍스트 | `#666978` | 설명, 캡션, 각주 |
| 구분선 | `#E4E5EC` | 표와 섹션 구분에만 사용 |
| 보조 면 | `#F5F5F8` | 주의사항·보조 설명의 제한적 배경 |
| 진한 면 | `#24243B` | 한 슬라이드의 핵심 대비 영역에만 선택적으로 사용 |

**폰트와 위계**
- 기본 글꼴: `Malgun Gothic`
- 프레젠테이션 제목: 50pt, Bold
- 슬라이드 제목: 35pt, Bold
- 본문·소제목: 20pt, Regular 또는 Bold
- 보조 설명·캡션·페이지 번호: 13pt
- 한 슬라이드의 텍스트 위계는 위 4단계를 넘지 않는다.
- 긴 제목을 임의로 축소하지 말고 문장을 줄이거나 레이아웃을 바꾼다.

**무드 & 레퍼런스**
- Y Combinator 데모데이 자료
- Airbnb 초기 피치덱
- 밝고 직접적이며 에너지가 있지만 과도하게 광고 같지 않은 초기 스타트업 문서

**디자인 특성**
- 넓은 여백과 명확한 좌측 정렬
- 슬라이드 제목만 읽어도 논리 흐름이 이어지는 구조
- 핵심 숫자·질문·한 문장을 크게 제시
- 실제 제품이나 참고 서비스는 공식 화면 캡처와 출처 링크를 함께 배치
- 아이콘보다 짧은 라벨, 숫자, 화살표와 선을 우선 사용
- 카드형 박스는 비교·단계·주의사항 등 정보 구조상 필요할 때만 제한적으로 사용

**텍스처**
- 없음

## 레이아웃 시스템
- 기본 캔버스: 16:9, `1280 × 720`
- 좌우 안전 여백: 72px
- 상단: 작은 영문 섹션 라벨 → 대제목 → 얇은 구분선
- 하단: 좌측 문서명, 우측 두 자리 페이지 번호
- 본문 시작선과 슬라이드 간 정렬 위치를 일정하게 유지한다.

**권장 페이지 유형**
1. 표지: 제목, 작성자, 최소한의 날짜·문서명만 배치한다.
2. 주장 + 화면: 좌측에 문제의식·해석, 우측에 공식 화면 캡처와 링크를 배치한다.
3. 판단 요청: 3~5개 요청사항을 번호, 질문, 보조 설명의 3열 구조로 정리한다.
4. 단계 흐름: 4~6개의 단계와 짧은 화살표를 한 줄로 연결한다.
5. 문제 → 해법 → 결과: 실제 사례와 수행 단계를 좌우 분할로 보여준다.
6. 3열 비교: 동일한 기준의 차이점을 세 개의 열로 정리한다.
7. 운영 범위: 현재 적용 범위와 공개 전 조건을 두 열로 분리한다.
8. 결론: 첫 질문을 다시 불러오고 필요한 판단 항목을 한 줄로 요약한다.

## 강조할 점 / 피할 점
- 강조: 발표의 핵심 판단, 서비스가 해결하는 문제, 실제 사용 흐름, 다음 행동
- 피할 것: 내부 작업 라벨, 요구사항 코드, AI 생성 과정, 불필요한 성능 과시, 근거 없는 숫자, 과도한 카드 그리드
- 피할 것: 제목·본문마다 제각각인 폰트 크기, 한 화면에 5단계 이상의 텍스트 위계
- 피할 것: 승인 요청 자료를 홍보 자료처럼 보이게 만드는 과장된 표현
- 피할 것: 실제 서비스 화면을 설명 없이 축소해 넣거나 출처 링크를 생략하는 방식

## 워딩 예시
- 좋은 제목: “시작 전 조직 판단 필요”
- 좋은 제목: “한 팀의 실패, 다음 학습자의 자산으로 전환”
- 좋은 본문: “반복 오류 발생”
- 좋은 본문: “교육생 계정 연동 검토”
- 좋은 본문: “외부 공개 전까지 사용 제한”
- 좋은 질문: “이 데이터를 외부에 공개해도 될까요?”
- 피할 표현: “외부 공개 전까지 사용을 제한합니다”
- 피할 표현: “검토가 필요한 상황입니다”
- 피할 표현: “혁신적인 AI 기반 차세대 플랫폼”
- 피할 표현: “압도적인 성과를 창출합니다”

## 문체 변환 기준
| 서술형 문장 | 권장 개조식 표현 |
|---|---|
| 반복 오류가 발생했습니다 | 반복 오류 발생 |
| 계정 연동을 검토하고 있습니다 | 계정 연동 검토 |
| 외부 사용자는 공개 전까지 차단합니다 | 외부 사용자 공개 전까지 차단 |
| 코어 백엔드 구축을 완료했습니다 | 코어 백엔드 구축 완료 |
| 조직의 판단이 필요합니다 | 조직 판단 필요 |

- 한 항목에는 하나의 사실이나 행동만 작성한다.
- 마침표는 완전한 문장이 필요한 인용·주의사항을 제외하고 생략한다.
- `진행`, `검토`, `필요`, `완료`, `발생`, `예정`, `제한`, `확인` 등 상태가 명확한 명사를 우선한다.

## QA 체크리스트
- 제목만 순서대로 읽어도 발표 논리가 이어지는가?
- 핵심 제안과 판단 요청이 첫 3장 안에 나오는가?
- 모든 슬라이드가 4단계 이하의 텍스트 위계를 사용하는가?
- 화면 캡처에 캡션과 출처 URL이 있는가?
- 텍스트 겹침, 잘림, 한 줄 제목의 예기치 않은 줄바꿈이 없는가?
- 내부 코드명과 제작 메모가 결과물에 노출되지 않았는가?

## 기타 요청
- 디자인만 바꾸는 작업에서는 원본의 표시 문구와 슬라이드 순서를 임의로 수정하지 않는다.
- 외부 자료와 화면 이미지는 슬라이드 노트의 `[Sources]` 블록에 출처를 기록한다.
