# PPT 스타일 가이드 예시 — 화이트페이퍼

> 사용법: 이 파일을 `reference/ppt-style.md`로 복사해 사용하거나, `/handoff ppt reference/examples/ppt-style-whitepaper.md`로 직접 지정한다.
> 이 가이드는 `SKALA_Code_Review_Lab_Manager_Briefing_Whitepaper.pptx`에서 사용한 시각 체계를 일반화한 것이다. 특정 프로젝트의 문구나 고유명사는 복제하지 않고 디자인 원칙만 재사용한다.

## 역할
전문 프레젠테이션 디자이너로서 학술 백서와 공식 보고서의 인쇄물 감각을 가진 슬라이드를 설계한다.

## 청중·목적
- 발표 대상: 경영진, 실무 매니저, 심사자, 공공·교육기관 관계자
- 발표 시간: 미지정
- 발표 목적: 근거, 구조, 판단 항목을 차분하고 신뢰감 있게 전달하며 화면 공유와 PDF 인쇄 모두에서 읽기 쉬운 자료를 만든다.

## 톤·어조
- 스타일: 화이트페이퍼, 카테고리: 심플
- 차분하고 공식적인 명사형·개조식 문체를 사용한다.
- `~합니다`, `~입니다`, `~했습니다` 같은 서술형 종결어미를 반복하지 않는다.
- `검토 필요`, `오류 발생`, `적용 예정`, `사용 제한`, `구축 완료`처럼 핵심 명사나 상태로 짧게 끝낸다.
- 한 항목에는 하나의 사실, 조건 또는 행동만 작성한다.
- 광고 문구와 과도한 감정 표현을 피하고 주장과 근거의 관계를 명료하게 쓴다.
- 장식보다 정보의 위계, 여백, 정렬로 완성도를 만든다.
- 승인권자의 답변이 필요한 문구는 예외적으로 짧은 의문형 사용을 허용한다.

## 분량·구성
- 권장 슬라이드 수: 8~14장
- 권장 흐름: 표지 → 배경·원천 아이디어 → 핵심 판단 → 구조·방법 → 사례 → 차별점 → 실행 기반 → 기대효과 → 운영 범위 → 결론
- 각 장은 보고서의 한 페이지처럼 독립적으로 읽히되 전체 논리가 누적되어야 한다.

## 디자인·시각 방향

**컬러 시스템**
| 용도 | 색상 | 사용 원칙 |
|---|---|---|
| 배경 | `#FAFAFA` | 순백색 대신 인쇄 용지에 가까운 기본 면 |
| 기본 텍스트 | `#374151` | 제목과 본문 |
| 강조·보조 | `#6B7280` | 섹션 라벨, 번호, 캡션 |
| 구분선 | `#D1D5DB` | 상단·하단 규칙선과 표 구분 |
| 옅은 면 | `#F3F4F6` | 표의 교대 행이나 제한적인 인용 영역 |

**폰트와 위계**
- 기본 글꼴: `Noto Serif KR`
- 프레젠테이션 제목: 46pt, Bold
- 슬라이드 제목: 35pt, Bold
- 본문·소제목: 18pt, Regular 또는 Bold
- 보조 설명·캡션·페이지 번호: 12pt
- 영문과 숫자도 같은 서체를 기본으로 사용해 문서 전체의 인쇄물 톤을 유지한다.
- 한 슬라이드의 텍스트 위계는 위 4단계를 넘지 않는다.

**무드 & 레퍼런스**
- 학술 백서
- 기관 연구보고서
- 공식 정책 문서와 편집 출판물
- 현대적인 세리프 타이포그래피를 사용한 인쇄용 프레젠테이션

**디자인 특성**
- 72px 이상의 넓은 좌우 여백
- 얇은 회색 규칙선과 평평한 직사각형
- 둥근 카드, 그림자, 그라데이션을 사용하지 않음
- 섹션 라벨과 페이지 번호를 작고 절제되게 배치
- 표와 단계 구조는 면보다 선과 간격으로 구분
- 강조색 대신 글자 굵기와 배치로 중요도를 표현

**텍스처**
- `#FAFAFA` 기반의 매우 옅은 종이 질감 2%
- 얼룩, 접힘, 빈티지 색감, 뚜렷한 섬유 무늬는 금지
- 프로젝터와 PDF 인쇄에서 본문 가독성을 해치지 않을 정도로만 적용

## 레이아웃 시스템
- 기본 캔버스: 16:9, `1280 × 720`
- 좌우 안전 여백: 72px
- 상단 구조: 작은 영문 섹션 라벨 → 대제목 → 1px 구분선
- 하단 구조: 1px 구분선 → 좌측 문서명 → 우측 두 자리 페이지 번호
- 일반 본문 영역: 상단 구분선 아래부터 하단 주석 영역 위까지 사용
- 주석·제약사항: 짧은 수평선과 한 줄 설명으로 처리하고 박스로 감싸지 않는다.

**권장 페이지 유형**
1. 표지: 상·하단 규칙선 사이에 제목과 작성자만 배치한다.
2. 원천 아이디어 + 화면: 좌측 설명, 우측 공식 캡처를 사각 프레임 안에 배치한다.
3. 판단 요청: 번호·질문·보조 설명을 보고서형 목록이나 교대 행으로 정리한다.
4. 프로세스: 4~6개 단계를 세로 구분선과 넓은 간격으로 나눈다.
5. 사례 분석: 문제 문장과 검증 절차를 두 열로 배치한다.
6. 비교: 세 개의 동일 폭 열을 사용하고 짧은 규칙선으로 제목을 구분한다.
7. 구조 설명: 두 개의 핵심 구조를 좌우에 두고 중앙 기호로 관계를 표현한다.
8. 기대효과: 대상·핵심 가치·파생 효과를 행 단위로 배치한다.
9. 운영 범위: 현재 적용 범위와 선행 조건을 중앙 세로선으로 분리한다.
10. 결론: 질문을 크게 제시하고 판단 범위와 다음 행동을 아래에 정리한다.

## 강조할 점 / 피할 점
- 강조: 근거, 결정 항목, 용어의 일관성, 페이지별 논리적 완결성
- 피할 것: 둥근 카드, 컬러 블록 남용, 아이콘 세트, 그림자, 글로우, 그라데이션
- 피할 것: 배경 질감이 텍스트보다 먼저 보이는 상태
- 피할 것: 지나치게 옅은 본문, 12pt 미만의 설명, 한 페이지에 과도한 문장
- 피할 것: 세리프와 산세리프를 규칙 없이 혼용하는 방식
- 피할 것: 레이아웃 변경 과정에서 원문을 축약하거나 단계 번호·기호를 임의로 바꾸는 행위

## 워딩 예시
- 좋은 제목: “시작 전 확인 범위”
- 좋은 제목: “검증 기반 우선 구축”
- 좋은 설명: “기대효과는 실측 전 단계”
- 좋은 설명: “반복 오류 발생”
- 좋은 설명: “외부 공개 기준 확인 필요”
- 피할 표현: “시작 전에 확인해야 할 범위가 있습니다”
- 피할 표현: “검증 기반을 먼저 구축했습니다”
- 피할 표현: “게임 체인저가 될 혁신적 솔루션”
- 피할 표현: “폭발적인 성장과 압도적인 성과”

## 문체 변환 기준
| 서술형 문장 | 권장 개조식 표현 |
|---|---|
| 반복 오류가 발생했습니다 | 반복 오류 발생 |
| 개인정보 처리 기준을 확인해야 합니다 | 개인정보 처리 기준 확인 필요 |
| 파일럿에서 효과를 측정할 예정입니다 | 파일럿 효과 측정 예정 |
| 외부 사용자는 공개 전까지 차단합니다 | 외부 사용자 공개 전까지 차단 |
| 검증 기반을 먼저 구축했습니다 | 검증 기반 우선 구축 |

- 조사와 연결어를 줄이고 핵심 명사 중심으로 작성한다.
- 마침표는 완전한 문장이 필요한 인용·주의사항을 제외하고 생략한다.
- `진행`, `검토`, `필요`, `완료`, `발생`, `예정`, `제한`, `확인` 등 상태가 명확한 명사를 우선한다.

## QA 체크리스트
- `Noto Serif KR`가 실제 PPTX의 텍스트 속성에 기록되어 있는가?
- 모든 페이지의 제목 위치와 상·하단 규칙선이 일치하는가?
- 페이지 번호가 동일한 위치와 형식으로 표시되는가?
- 종이 질감이 본문 가독성을 방해하지 않는가?
- 둥근 모서리, 그림자, 불필요한 색상 면이 남아 있지 않은가?
- 원본 기반 재디자인이라면 전체 표시 문구가 원본과 일치하는가?
- 텍스트 겹침, 잘림, 캔버스 초과가 없는가?

## 기타 요청
- 디자인만 바꾸는 작업에서는 원본의 표시 문구, 번호, 화살표와 슬라이드 순서를 임의로 수정하지 않는다.
- 외부 자료와 화면 이미지는 슬라이드 노트의 `[Sources]` 블록에 출처를 기록한다.
- 결과물 제출 전 전체 슬라이드를 실제 PowerPoint 렌더링 기준으로 확인한다.
