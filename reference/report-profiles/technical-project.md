# 보고서 프로필: technical-project

교육 실습과 개발 프로젝트의 구현·검증 보고서에 사용한다.

## 판단 질문

독자는 이 결과물이 요구사항을 충족하며 같은 조건에서 재현 가능한지 판단한다. 구현량보다
설계 선택의 이유, 정상·오류 경계, 실행 증거, 남은 위험을 우선한다.

## 기본 구성

1. **결론과 핵심 결과** — 완료 범위, 대표 결과, 재현 조건, 가장 중요한 한계
2. **문제와 요구사항** — 프로젝트에만 해당하는 제약과 성공 조건
3. **설계 결정** — 채택안, 대안, 선택 근거, 뒤집은 결정
4. **구현과 실행 결과** — 핵심 흐름과 판독 가능한 실행 증거
5. **검증** — 정상·오류·경계 시나리오, 환경, 명령, 결과
6. **한계와 인수인계** — 미검증 범위, 알려진 문제, 다음 작업

빈 절은 삭제한다. 파일 목록과 기술 스택을 본문 앞에 관성적으로 나열하지 않는다.

## 증거 우선순위

직접 실행 결과와 테스트 로그, 요구사항 명세, 현재 코드 위치, 설정, 커밋·PR 순으로 사용한다.
화면 캡처는 상태 코드·입력·응답이 판독될 때만 증거다. 코드 캡처보다 테스트 결과와 재현
명령을 우선한다.

## 권장 시각화

- 요구사항–구현–검증 대응표
- 핵심 실행 흐름 3~5단계
- 정상·오류 시나리오 결과표
- 계획 대비 변경 사항과 영향

레이어 구조나 기술 스택 로고는 독자의 판단에 필요할 때만 넣는다.
