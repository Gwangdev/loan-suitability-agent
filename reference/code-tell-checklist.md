# 코드 AI 흔적 체크리스트

> `ai-tell-checklist.md`의 코드 대칭판. 그쪽은 산문(보고서·공개 초안), 이쪽은 소스코드와 저장소를 다룬다.
> `/verify`의 `independent-verifier`가 이 목록으로 검증한다. 기계 검출은 `tools/gate.py`가 수행한다.
>
> 목적은 위장이 아니다. 아래 항목의 대부분은 **실제 결함**이며, 고치면 코드가 실제로 좋아진다.
> 지문이 사라지는 것은 부수효과다.

## 0. 저장소 위생 (가장 먼저 — 코드를 열기 전에 걸린다)

| 흔적 | 증상 | 교정 |
|---|---|---|
| 도구 흔적 | `.claude/settings.local.json`, `.superpowers/`, `.aider*`, 세션 토큰·PID 파일 | `.gitignore` 등록 후 추적 해제 |
| 빌드 산출물 | `build/`, `bin/`, `.gradle/`, `__pycache__/`, `.DS_Store` | 동일 |
| 프롬프트 원문 | 생성 프롬프트·하네스 문서가 산출물에 동봉 | 제출 범위에서 분리 |
| 식별정보 | 과정·팀·개인 이메일이 공개 저장소에 잔존 | 공개 전 스캔. `noreply` 주소 사용 |

**`.gitignore` 부재는 그 자체가 최상위 신호다.** 산출물이 통째로 추적된다는 뜻이다.

## 1. 주석

| 흔적 | 증상 | 교정 |
|---|---|---|
| 서술형 주석 | 바로 아래 줄을 한국어로 옮김 (`// 잔액 차감` → `balance -= x`) | 삭제. 주석은 **'왜'만** 남긴다 |
| 균일 밀도 | 모든 함수에 독스트링. 커버리지 100% | 자명한 매퍼·헬퍼·getter에서 걷어낸다. **편차 0이 신호다** |
| 문장 복제 | 같은 근거 문장이 두 파일에 글자 단위로 동일 | 한 곳만 남기고 나머지는 삭제하거나 다시 쓴다. **템플릿 적용의 직접 증거** |
| 층위 중복 | 같은 근거를 독스트링과 인라인 주석에 두 번 | 한 곳에만 |
| 구획 배너 | `# ────────`, `// =======` 가 모든 절에 균일 | 삭제 |
| 과잉 단언 | 코드가 보장하지 않는 성질을 주석이 단언 (`원자적으로 처리된다`, `스레드 안전`, `오차 없음`) | **결함 신호다.** 코드를 고치거나 보장 범위를 정확히 쓴다 |

**목표 비율: 인라인 주석 중 '왜'형 40% 이상.** 절대 기준이 아니라 본인 저장소 간 추세로 본다.

## 2. 구조

| 흔적 | 증상 | 교정 |
|---|---|---|
| 조기 추상화 | 호출부 2곳 이하인 헬퍼·상수·인터페이스·기본값 파라미터 | 인라인화 |
| 대칭 과잉 | 병렬 클래스의 메서드 순서·이름이 완전히 동일 | 실제 필요에 따라 비대칭 허용. **단 사유를 남기지 않은 비대칭은 결함이다** → `design-review-checklist.md` §1 |
| 균일 방어 | 모든 층위에 같은 입도의 예외 처리, 발생 불가능한 상황까지 방어 | 실제 실패 경험이 있는 경계에만 |
| 명명 균질 | 추상화 수준과 격식이 완전히 고른 이름 | 도메인 약어·짧은 지역 변수 허용 |
| 시대 불일치 | 주변 코드와 라이브러리 세대가 안 맞음 (deprecated API) | **인접 파일 3~5개를 컨텍스트로 주입**하면 대부분 해결 |

## 3. 흔적 없음 (too clean)

- `TODO`·`FIXME`·미사용 import·주석 처리된 이전 구현이 **0건**이면 신호다.
- **미완성 공개 표면은 여기에 해당하지 않는다.** 호출되지 않는 public 메서드·엔드포인트는 시간의 흔적이 아니라 기능 누락이며, `design-review-checklist.md` §2에서 결함으로 다룬다.
- 커밋 이력에 `fixup`·`revert`·오타 수정이 **0건**이면 신호다. squash하지 말고 남긴다.
- **인위적으로 만들지 않는다.** 가짜 오타·가짜 낡은 주석은 리뷰어가 즉시 알아보고 유지보수 비용만 는다.
  시간과 리뷰가 만들게 두는 것이 유일한 정답이다.

## 4. 이력 — 인간 신호의 유일한 진짜 원천

검증에서 나온 지적을 **코드 주석으로 되먹인다.** 형식을 고정한다.

```python
# 예전엔 existsByStockId()로 선행 검사한 뒤 delete()를 호출했다.
#          검사와 삭제 사이에 참조가 삽입될 수 있어(TOCTOU) 검사가 무의미했다.
#          DB 제약 위반을 잡아 도메인 예외로 변환하는 방식으로 교체.
```

세 요소가 다 있어야 한다: **과거 상태 / 무엇이 틀렸나 / 어떻게 바꿨나.**
지적 하나당 회귀 테스트 하나를 만들고, 지적 내용이 테스트 이름에 남게 한다.

> `test_hard_verdict_has_no_recommendation`

**태그·번호를 코드에 쓰지 않는다.** 코드는 제출물이고, 하네스 작업용 표기는 제3자에게 의미가 없다. 읽는 사람에게 필요한 것은 위 세 요소뿐이며 출처·번호는 그중 어디에도 들어가지 않는다. 지적과 코드의 대응은 `PROJECT_LOG.md`의 피드백 대장이 `커밋 해시`·`파일:라인`으로 갖는다. 게이트 `L2`가 코드 내 태그를 BLOCK한다.

이 규약이 없으면 검증 결과가 상태 파일에만 남고 코드에는 역사가 남지 않는다.
피드백 대장은 검증의 기록이고, 코드 주석은 **판단의 기록**이다. 둘 다 필요하다.

## 5. 주장 대 실제

산출물이 하지 않은 일을 했다고 주장하는지 확인한다. 문체가 아니라 **신뢰의 문제**다.

- 커밋 메시지가 "제거·정리·삭제"를 표방했는데 실제 diff의 삭제 라인이 0~2줄
- 주석이 보장한 성질을 코드가 제공하지 않음 (§1 과잉 단언)
- 문서가 "전 항목 완료"라고 했는데 미달 항목이 있음

```bash
# 삭제를 표방한 커밋의 실제 변경량 확인
git log --format='%h %s' | grep -E "제거|삭제|정리|remove|clean" | while read h s; do
  echo "$s → $(git show --shortstat --format='' $h | tail -1)"
done
```

## 6. 자동 검출

```bash
python3 tools/gate.py .
```

BLOCK 0건이 될 때까지 제출·발행하지 않는다. 검사 항목과 코드는 `tools/gate.py` 상단 주석 참조.
