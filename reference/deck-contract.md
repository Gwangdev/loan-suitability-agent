# 슬라이드 콘텐츠 계약 (교체 불가)

> **`ppt-style.md`와 역할이 다르다.** 스타일 파일은 시각·톤을 정하고 교체할 수 있다.
> 이 파일은 **내용의 구조**를 정하며 스타일 파일로 덮어쓸 수 없다. `tools/gate.py`의 `K1~K9`이 검사한다.

## 전제 — AI 티는 문체가 아니다

문체를 다듬어도 AI가 쓴 티는 사라지지 않는다. 원인이 세 가지 구조에 있기 때문이다.

| 원인 | 증상 | 검사 |
|---|---|---|
| **판단의 부재** | 임계값·실패조건 없이 "검토한다"로 끝남 | `K1` `K2` |
| **과도한 대칭** | 모든 장이 불릿 4개, 모든 줄이 같은 길이 | `K4` `K5` |
| **도메인 무국적성** | 예시가 제조·금융·헬스케어를 골고루 순회 | `K8` |

오타를 심어 사람 흉내를 내는 방식은 쓰지 않는다. 역효과다.

## 산출 형식

슬라이드를 바로 쓰지 않고 **`deck.json`을 먼저 쓴다.** 게이트가 대조할 수 있는 형태여야 검증이 의견이 아니라 판정이 된다. 코드에 `SPEC.yaml`이 있는 것과 같은 이유다.

```json
{
  "meta": {
    "title": "전처리 실무",
    "audience": "3~7년차 제조 데이터 분석가",
    "subject_domain": "it",
    "home_domain": "ecommerce",
    "version": "1"
  },
  "slides": [
    {
      "id": "s1",
      "kind": "technique",
      "title": "결측 처리",
      "subtitle": "결측은 제거 대상이 아니라 설비 상태의 신호임",
      "probe": "결측이 특정 호기에만 몰려 있다면 그건 결측인가 고장인가?",
      "blocks": [
        {
          "label": "How",
          "items": [
            {
              "text": "결측 10% 이하면 row 제거",
              "threshold": "10%",
              "failure_mode": "결측이 특정 라인에 몰려 있으면 그 라인이 통째로 사라짐"
            }
          ]
        }
      ]
    }
  ]
}
```

`kind`: `section` · `concept` · `technique` · `matrix` · `case` · `closing`
`label`: `Concept` · `Why?` · `How` · `Pros & Cons` · `유의할 점` · `Recommendation` · `Think to look for`

## 규칙

**1. 방법에는 실패 조건을 단다 (`K2`, BLOCK)**
`How`·`Recommendation` 항목은 `failure_mode`가 필수다. 그 방법이 **오히려 해가 되는 구체적 상황**을 쓴다.

- 나쁨: `이상치에 주의`
- 좋음: `이상치 1개가 나머지 전부를 0 근처로 압축`

「주의가 필요함」은 실패 조건이 아니다. 조건을 쓴다.

**2. 전체 항목의 15% 이상에 수치 기준을 넣는다 (`K1`, BLOCK)**
기준이 정말 없으면 `threshold`를 비우되, 비운 항목이 많으면 실패한다.
**기억이 불확실한 수치는 지어내지 않는다.** 비워 두고 본문에 「현장 기준으로 합의」로 처리한다.

**3. 예시를 한 도메인에 몰아라 (`K8`, WARN)**
`home_domain`을 정하고 그 분야 어휘로만 예시를 든다. 여러 도메인을 순회하는 순간 생성물 티가 난다.
사람은 자기 밥벌이 도메인에 쏠려서 쓴다.

**주제 도메인과 예시 도메인은 다르다.** IT 강의는 `엔드포인트`·`트랜잭션` 같은 주제어가 전 슬라이드에 깔린다. 그것을 예시 도메인으로 세면 카운트가 포화돼 검사가 무력해진다. 그래서 둘을 나눠 선언한다.

```json
"subject_domain": "it",        // 강의 주제. 드리프트 계산에서 제외된다
"home_domain": "ecommerce"     // 예시가 쏠려야 할 곳. 이것만 검사한다
```

**주제가 IT인 강의는 `subject_domain: "it"`을 반드시 넣는다.** 넣지 않으면 예시를 제조·헬스케어·금융으로 흩뿌려도 통과한다.
`home_domain`은 배열도 된다(`["ecommerce", "finance"]`). 다만 늘릴수록 검사가 느슨해진다.

선택지: `manufacturing` · `finance` · `healthcare` · `ecommerce` · `telco` · `public` · `it` · `generic`

**4. `concept`·`technique` 슬라이드에 `probe` 1개 (`K3`, WARN)**
**슬라이드가 답하지 않는** 질문이어야 한다. 본문에 답이 있으면 probe가 아니다.

**5. 의도적으로 비대칭하게 쓴다 (`K4`·`K5`, WARN)**
어떤 장은 불릿 3개, 어떤 장은 6개. 어떤 줄은 6자, 어떤 줄은 45자.
모든 장이 같은 구성이면 실패다. **균일함이 곧 AI 지문이다.**

**6. 내용 없는 수식어 금지 (`K6`, BLOCK)**
`매우 중요` `필수적` `다양한` `효과적으로` `적절하게` `종합적으로` `전반적으로` 등.
삭제하거나 수치로 대체한다.

**7. 명사형 종결 (`K7`, WARN)**
`~음` `~함` `~됨`. `~합니다`·`~이다`는 쓰지 않는다.
영문 기술용어는 번역하지 않는다(Scaling, Outlier, Encoding).
`Reduce X / Improve Y / Stabilize Z` 같은 완벽한 영문 동사구 병렬은 3개 이상 늘어놓지 않는다.

**8. 부제는 주장이다 (`K9`, WARN)**
제목의 부연이 아니다.

- 나쁨: `Outlier 탐지 방법`
- 좋음: `통계적 이상치와 공정상 이상은 같은 것이 아니다`

**9. 한 슬라이드 = 개념 1개, 본문 9줄 이하 (`K9`, BLOCK)**
넘치면 슬라이드를 쪼갠다.

**10. 줄바꿈은 어절 단위 (`K10`, WARN)**
`text`·`title`·`subtitle`에 손으로 넣는 줄바꿈(`\n`)은 어절 경계에만 둔다.
줄 길이를 맞추려고 어절 중간을 끊지 않는다. 끊을 자리가 없으면 문구를 줄인다.
시각 규칙이 아니라 가독성 규칙이므로 `ppt-style.md`로 덮어쓸 수 없다.

- 나쁨: `결측이 특정 라인에 몰려 있으면 그 라인이 통\n째로 사라짐`
- 좋음: `결측이 특정 라인에 몰려 있으면\n그 라인이 통째로 사라짐`

## 사람이 채워야 하는 입력 — 질문 5개

`/handoff ppt`가 시작할 때 묻는다. **사용자가 이 JSON 스키마를 직접 볼 일은 없다.**

| # | 질문 | 채우는 곳 |
|---|---|---|
| 1 | 주제와 슬라이드 수 | `meta.title` |
| 2 | 대상 — **직군·연차까지** | `meta.audience` |
| 3 | 강의 **주제** 도메인 | `meta.subject_domain` |
| 4 | **예시**를 몰아넣을 도메인 | `meta.home_domain` |
| 5 | **반드시 담아야 할 실무 판단 3가지** | 본문 전체 |

2번에 「실무자」처럼 뭉뚱그린 답이 오면 다시 묻는다. 대상이 흐리면 교과서 난이도로 쓰인다.

**5번이 이 계약의 유일한 방어선이다.** 비워 두면 LLM은 교과서를 요약하고, 그 순간 AI 티가 난다.
게이트는 형식만 본다 — `failure_mode`에 「주의가 필요함」을 넣어도 통과한다. **내용의 진위는 사람이 판정한다.**

## 한계

- **린터는 형식만 본다.** 규칙을 프롬프트에 그대로 넣었으므로 형식만 맞춘 껍데기를 만들 수 있다
- 임계값(`K1` 15%, `K4` 0.6, `K5` 8.0)은 잠정이다. 몇 번 써보고 `tools/gate.py` 상단에서 조정한다
- `DOMAIN_LEXICON`에 **자기 현장 어휘를 추가하는 것이 체감 효과가 가장 크다**
- `it` 어휘는 백엔드·인프라 중심으로 채워져 있다. 프론트엔드·데이터 엔지니어링 용어는 필요할 때 `tools/gate.py`의 `DOMAIN_LEXICON`에 추가한다
