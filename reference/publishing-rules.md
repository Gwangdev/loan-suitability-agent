# 포트폴리오·기술 블로그 자동화 규칙

## 원본과 파생물
- 원본: 코드·테스트·Git 기록·`PROJECT_STATE.md`·`PROJECT_LOG.md`·사용자가 제공한 대화 요약.
- **상태 파일은 근거로만 쓰고 발행하지 않는다.** `PROJECT_STATE.md`·`PROJECT_LOG.md`와 작업용 라벨은 하네스 내부 자산이다(게이트 `L1`·`L2`).
- 구조화 원본: `docs/portfolio/project.yaml`.
- 파생물: README·Notion·블로그·이력서·보고서. 파생물에서 원본 사실을 새로 만들지 않는다.

## 승인 단계
`evidence → draft → reviewed → approved → published`

- 기본은 `draft`까지만 자동화한다.
- Notion 업로드, 블로그 발행, Git push는 외부 전송이므로 별도 승인한다.
- 자동 생성 영역과 수동 수정 영역은 마커로 분리한다(`/handoff` 재실행 규칙 참조).

## 금지
- 실제 구현하지 않은 기능 기재
- 팀 작업을 개인 작업으로 표현
- 근거 없는 성능·시간 절감 수치 생성
- 기밀·개인정보·API 키·내부 URL 공개
- 대화 원문 전체를 공개 문서로 복사
- 상태 파일·피드백 대장·작업용 라벨을 공개 문서에 그대로 옮기기

## 민감정보 스캔 (public 산출물 생성 전 필수)

```bash
grep -rnE "sk-[A-Za-z0-9]{16,}|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{20,}|xox[baprs]-|-----BEGIN [A-Z ]*PRIVATE KEY-----|Bearer [A-Za-z0-9._-]{20,}|password\s*[:=]|passwd\s*[:=]|secret\s*[:=]|api[_-]?key\s*[:=]" <대상경로>

grep -rnE "([0-9]{1,3}\.){3}[0-9]{1,3}|localhost:[0-9]+|\.internal\b|\.local\b|10\.[0-9]+\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\." <대상경로>

grep -rnE "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|01[0-9]-?[0-9]{3,4}-?[0-9]{4}|[0-9]{6}-[1-4][0-9]{6}" <대상경로>
```

- `.env`, `*.pem`, `*.key`, `credentials*`, `secrets*` 파일은 근거로도 인용하지 않는다.
- 검출 시 `public/` 생성을 중단하고 사용자에게 목록을 보고한다. 자동 마스킹으로 넘어가지 않는다.
- 사용자가 제공한 대화 내보내기 파일은 키·토큰이 섞여 있을 확률이 높으므로 **반드시 스캔 대상에 포함**한다.

## 대화 활용
- AI 대화는 기획 배경·의사결정·트러블슈팅 후보를 찾는 보조 근거다.
- 현재 세션 밖의 대화에 자동 접근할 수 있다고 가정하지 않는다.
- 대화 내보내기 또는 사용자가 승인한 요약 파일을 입력으로 사용한다.
