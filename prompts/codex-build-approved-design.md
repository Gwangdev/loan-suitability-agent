# 작업 순서

각 단계가 끝날 때마다 `python3.11 -m pytest`와 `python3 tools/gate.py .`를 돌린다.
**현재 기준선: `pytest 89 passed` · `gate BLOCK 1(G3) · WARN 9` · `S3`·`S4` 0건.**
`G3`는 원리상 해소 불가이므로 **BLOCK 1은 정상이다.** 그 외 BLOCK이 새로 생기면 멈춰라.

## 단계 2 — 안 B 이행 (ADR-029 · ADR-030)

### 2-1. `ADR-029` 파싱 경계 이중화

`POST /api/v1/parsing-preview`가 **규칙 파서와 LLM 파서를 나란히 실행하고 불일치를 응답에 싣는다.**

지켜야 할 것:

- **자동으로 화해시키지 마라.** 어느 쪽을 채택할지 코드가 정하면 그 값은 다시 검증되지 않는다. 응답은 두 결과와 **불일치 필드 목록**을 담고, 사람이 화면에서 고른다
- **저하는 되지만 실패하지 않는다.** LLM 키가 없으면 규칙 파서 결과만 담고 **그 사실을 응답에 표시**한다. 200으로 나간다 — 파서 하나가 없어도 R5의 계약(구조화 후보 반환)은 지켜진다
- **저장하지 않는다.** R5 그대로다
- **엔드포인트를 추가하지 마라.** 기존 R5 하나다
- LLM 파서는 `core.py`에 이미 있는 Agent 1 프롬프트를 재사용한다. **짧은 JSON 1회 호출**이어야 한다

**부수 효과 — `#18` 해소.** Eval의 「파싱정확도」 지표가 채점 대상을 갖게 된다. `loan_agent/eval.py`의 해당 지표를 이 경로의 출력에 배선하라.

**요구되는 테스트:** 두 파서가 일치할 때 / 불일치할 때 / LLM 키가 없을 때 — 세 경우의 응답 형상

### 2-2. `ADR-030` 안내문 1회 호출

현재 LLM 왕복 5회(파싱 1 + 심사 도구 2 + 안내 도구 2)를 **1회로 줄인다.**

- **확정된 판정·DSR·추천상품 상세를 프롬프트에 데이터로 주입**하고 안내문만 받는다
- `assess_loan_eligibility`·`lookup_loan_product` **도구 왕복 4회를 제거**한다
- **ADR-025가 선행 조건이다** — 추천 항목이 상품명·은행·금리범위·한도를 이미 실어야 `lookup` 왕복이 불필요해진다. 안 실려 있으면 그것부터
- **스트리밍은 하지 마라.** ADR-030이 의도적으로 보류했다(ADR-007과 충돌). 측정이 먼저다
- 디스클레이머 강제 삽입과 Eval 게이트는 **그대로 유지**한다(ADR-007)

**주의 — 재생성 필요:** `loan_agent/demo_fixtures.json`은 3-Agent 형식의 녹화 출력이다. 파이프라인이 바뀌면 **오너 키로 1회 다시 구워야 한다.** 너는 키가 없으므로 **재생성이 필요하다는 사실만 보고하고 파일을 건드리지 마라.**
`loan_agent/eval_cases.json`은 손으로 만든 케이스라 형식 유지가 가능하다.

**측정하라 — 합격 기준은 없다.** `run_service_with_stages(on_stage=...)`가 단계 완료를 통지한다. **단계별 소요 시간을 실측해 보고하라.** 이 프로젝트의 규칙은 「측정에 합격 기준을 두지 않는다. 알아야 할 것은 어디서 꺾이는가다」이다.

### 2-3. `ADR-024 §24-R` 실행 주체 분기

`POST /api/v1/assessments/{id}/explanation-runs`에 **키 헤더가 오면 `app`이 동기 실행**한다. 없으면 지금처럼 `PENDING`만 만든다.

**반드시 지켜라 — 여기서 틀리기 쉽다:**

1. **기존 `PENDING` 행을 집어 실행한다. 409로 막지 마라.** 심사 생성 트랜잭션이 `PENDING`을 함께 만들므로(ADR-003 아웃박스) 409로 막으면 **방문자가 항상 409를 받는다.** ADR-019의 409는 **`RUNNING` 중 재요청에만** 적용된다
2. **200초를 넘긴 `RUNNING` 행도 함께 집는다** (§24-R-a). 운영에 워커가 없어서 아무도 회수하지 않으면 그 심사는 영원히 막힌다
3. **행을 `RUNNING`으로 바꿔 커밋하고 커넥션을 놓은 뒤** LLM을 부른다(ADR-023 §23.1). **트랜잭션을 쥔 채 부르면 ADR-003 위반이다**
4. **상한 초과는 `503`으로 나간다** (§24-R-b). **504를 만들지 마라**
5. **키를 저장하지 마라.** 인자로만 흐른다
6. 워커 경로(서버 키)는 **그대로 둔다.** 두 경로가 같은 `explanation_run` 행을 집고 같은 컬럼을 채운다

**요구되는 테스트:** 방문자 키로 동기 실행 → 완료된 실행 반환 · 기존 `PENDING`을 집는지 · `RUNNING` 중 재요청은 409 · 스테일 `RUNNING` 회수 · LLM 실패 시 판정 보존

### 2-4. `#29` dsr 왕복 타입 — 같은 패스에서 고친다

`loan_agent/db/models.py:107`

```python
dsr: Mapped[float] = mapped_column(Numeric, nullable=False)
```

SQLAlchemy `Numeric`은 `asdecimal=True`가 기본이라 **읽을 때 `Decimal`을 돌려준다.** 쓸 때는 `float`가 들어간다. 타입 힌트가 왕복의 절반만 참이고, 읽은 값을 `float`와 섞어 산술하면 `TypeError`가 난다. precision·scale도 없다.

- 타입 힌트를 **실제 왕복 타입에 맞춘다**
- precision·scale을 **명시한다**
- **`float` → `Decimal` 전면 전환은 하지 마라.** ADR-032가 측정으로 기각했다
- **DB 왕복 타입을 단언하는 통합 테스트를 추가하라.** 현재 `tests/test_assessments.py:56`은 `body["dsr"] >= 0`만 본다 — 없으면 같은 오류가 다시 들어온다

### 2-5. `#26` 잘못된 테스트를 의도적으로 뒤집는다

`tests/test_ui_api_client.py:30`이 **ADR-027이 결함으로 판정한 멱등 동작을 정답으로 고정**해 두었다. 멱등 키는 내용 해시가 아니라 **클라이언트가 조작마다 만드는 `uuid4`**다.

**테스트 이름까지 뒤집어라.** 단언만 고치면 이름이 옛 오해를 계속 가리킨다.
