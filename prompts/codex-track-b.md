# Codex 작업 지시 — Track B (병렬 트랙)

## 상황

`loan-suitability-agent` — 대출 상담 의사결정 지원 서비스. FastAPI로 재작성 중이다.
브랜치 `feature/decision-support-rebuild`, 현재 커밋 6건까지 진행됐다.

**다른 세션이 같은 작업 트리에서 Track A(영속화 계층)를 동시에 진행한다.**
그래서 파일 소유권이 나뉘어 있다. 아래 「내 파일」 밖은 읽기만 하고 쓰지 않는다.

## 먼저 읽어라

내용을 이 프롬프트에 옮겨 적지 않았다. **파일을 직접 열어라.** 그래야 다른 세션과 같은
근거를 보고 같은 결론에 도달한다.

| 파일 | 무엇이 있는가 |
|---|---|
| `SPEC.yaml` | 공개 표면 명세 9개. **여기 없는 엔드포인트를 만들면 게이트가 BLOCK한다** |
| `docs/설계결정.md` | ADR 22건. 각 항목에 **기각한 대안과 사유**가 함께 있다 |
| `docs/데이터모델.md` | ERD·상태 전이·제약·인덱스 |
| `docs/리스크_통제_대장.md` | 법적·보안 리스크와 통제 |
| `PROJECT_LOG.md` §구현 상태 | **항목 1에서 확정한 관례.** 이것을 복제한다 |
| `reference/insights/backend-hardening.md` | 하드닝 원칙. **미적용은 결함이며 사유 없이 넘기지 않는다** |

## 절대 규칙

1. **커밋하지 마라.** `git commit`·`git push`·`git checkout`·`git stash` 금지.
   변경만 남기고 보고한다. 커밋은 체크포인트에서 한 번에 쪼개 만든다.
2. **`SPEC.yaml`에 없는 공개 표면을 만들지 마라.** 필요하다고 느끼면 만들지 말고 보고해라.
3. **아래 「내 파일」 밖의 파일을 수정하지 마라.** 다른 세션이 동시에 작업 중이다.
4. **주석에 태그·번호를 쓰지 마라.** `[피드백N]`·`[디벨롭]` 같은 표기는 게이트 `L2`가 BLOCK한다.
   원인 → 과정 → 결론을 자연어로, 저장소를 처음 보는 사람이 읽는다고 가정하고 쓴다.
5. **테스트를 먼저 쓰고 실패를 확인한 뒤 구현해라.** 새 테스트가 곧바로 통과하면 이미
   구현됐거나 아무것도 검사하지 않는 것이다. 어느 쪽인지 확인 전에 넘어가지 않는다.
6. **`pytest`를 항상 green으로 유지해라.** 다른 세션이 같은 트리에서 테스트를 돌린다.
   중간 상태로 오래 두지 마라.

## 환경

```bash
pytest                        # 테스트. python3는 3.14로 잡혀 의존성이 없다
python3.11 tools/gate.py .    # 게이트. python3로 돌리지 마라
```

## 검증 — 작업 후 반드시 실행

```bash
pytest
python3.11 tools/gate.py .
```

**현재 기준선은 `BLOCK 2 · WARN 11`이다.**

| 기존 BLOCK | 내용 |
|---|---|
| `G3` | 과거 커밋 이력. 이력 재작성 없이는 해소 불가. 판정 완료 |
| `S3` 8건 | 아직 구현하지 않은 명세 항목. Track A가 채운다 |

기존 WARN 11건도 전부 판정이 끝난 것이다(`A5`·`C1`·`C4`·`C5`·`D2`·`G1`·`G4`·`I3`·`P2`·`S2`·`T2`).
**새로 늘어난 BLOCK·WARN만 네 책임이다.** 늘었으면 원인을 보고해라.

# B1 + B2 — 배포 구성과 CI (함께 한다)

둘 다 PostgreSQL을 정의하므로 따로 하면 설정이 갈라진다.

**내 파일:** `docker-compose.yml`(신규) · `Dockerfile` · `.dockerignore` · `.github/workflows/ci.yml`

## B1. Compose 3-tier + Dockerfile 하드닝

`docs/설계결정.md`의 **ADR-011**이 계층 구성을 정해뒀다. 그대로 구현해라.

| 계층 | 서비스 | 네트워크 | 호스트 노출 |
|---|---|---|---|
| Presentation | `ui` (Streamlit) | `frontend` | 노출 |
| Application | `app` (FastAPI) | `frontend` + `backend` | 노출 |
| Data | `postgres` | `backend` **전용** | **미노출** |

- **`postgres`에 호스트 포트를 게시하지 마라.** 게이트 `I1`이 잡는다
- **`postgres`를 내부 전용 네트워크에만 둬라.** 게이트 `I5`. 앱이 뚫려도 데이터 계층이
  밖으로 나가는 경로가 존재하지 않게 만드는 것이 목적이다
- **non-root와 read-only 루트 파일시스템을 한 세트로 적용해라.** 게이트 `I2`.
  read-only만 켜면 쓰기가 필요한 경로가 드러나므로 그 경로를 개별 허용하는 작업이 함께 온다.
  한쪽만 적용한 구성은 미완료로 판정된다
- **`postgres`에 healthcheck를 걸고 `app`이 그것을 기다리게 해라.** 게이트 `I3`.
  `depends_on`만으로는 「떠 있는 순서」만 보장되고 「받을 준비」는 보장되지 않는다
- **로그 로테이션을 걸어라**(ADR-016 채택). 여러 서비스에 같은 값을 쓰므로 YAML 앵커로
  한 번만 정의한다
- **리소스 상한은 ADR-016이 조건부 채택이다.** `docker compose config`로 해석 결과를 출력해
  런타임이 실제로 반영하는지 확인해라. 조용히 무시되면 **그 사실을 보고하고 채택을 보류해라** —
  「상한을 걸었다」는 문서상 사실만 남는 것이 가장 나쁘다
- DB 어드민 UI 같은 관리 도구를 기본 기동 대상에 넣지 마라. 켜져 있는 시간이 곧 공격 표면이다
- 자격증명을 compose 파일에 박지 마라. **인용부호 없는 목록형(`- KEY=값`)도 박은 것과 같다**

`app`을 호스트에 노출하는 것은 **의도된 타협**이다(Swagger를 포트폴리오 증거로 쓴다).
사유가 리스크 대장 B3에 적혀 있으니 임의로 바꾸지 마라.

## B2. CI에 PostgreSQL 추가

현재 CI는 경량 의존성만 설치해 DB 없는 테스트만 돈다. Track A가 곧 DB 통합 테스트를
넣으므로 러너에 PostgreSQL을 띄운다.

- **`services: postgres`**(GitHub Actions 내장)를 쓴다. **Testcontainers는 CI에서 쓰지 마라** —
  도커 안의 도커라 느리고 설정이 까다롭다. 로컬은 compose·Testcontainers, CI는 services다
- **테스트 코드는 `DATABASE_URL` 환경변수로 접속처만 받는다.** 어느 쪽에서 돌든 코드가
  같아야 한다. 이 변수 이름을 바꾸지 마라 — Track A가 같은 이름을 쓴다
- **healthcheck(`--health-cmd pg_isready`)를 반드시 넣어라.** 없으면 컨테이너가 뜬 것과
  연결을 받을 준비가 된 것을 구분하지 못해 테스트가 간헐적으로 실패한다
- Python 3.11 유지. DB 드라이버가 의존성에 추가된다
- 워크플로에 남은 개발 이력용 주석이 있으면 원인 → 과정 → 결론 서술로 정리해라

# B3 — Eval 케이스 확대 + 결함 주입 (독립. 따로 돌려도 된다)

**내 파일:** `loan_agent/eval.py` · `tests/test_eval.py` · 필요 시 픽스처

`docs/평가리포트.md`를 먼저 읽어라. 현재 6지표 5케이스로 30/30이다.

## 축을 헷갈리지 마라 — 이게 이 작업의 핵심이다

| 축 | 무엇을 보는가 | 방법 |
|---|---|---|
| **Eval** ← 네 담당 | 출력 **내용**의 품질 | 녹화된 출력을 규칙으로 채점 |
| API 통합 테스트 | 실패 **경로**의 처리 | 다른 트랙이 한다. **여기서 하지 마라** |

판별 기준: **「출력이 있고 그 내용을 채점하는가」면 Eval이다.**
「출력이 오지 않거나 형태가 깨졌을 때 시스템이 어떻게 되는가」면 통합 테스트이고 네 담당이 아니다.

따라서 **LLM 타임아웃·스키마 실패는 다루지 마라.** 녹화 픽스처로는 타임아웃을 만들 수 없다.

## 확대할 케이스 — 경계·적대적 위주로 10~15건

- DSR 30%·40% 경계
- 한도 정확히 일치 / 1원 초과
- 소득 0, 신용등급 범위 밖, 필수정보 누락
- 모호한 금액 표현 — 한글 수사(`삼천만원`), 단위 생략(`월 300`)
- **프롬프트 인젝션 입력** — 판정이 불변이고 디스클레이머가 유지되는지 확인.
  이 프로젝트는 인젝션을 필터로 막지 않고 **판정을 LLM 밖에 두어 공격 대상을 없앴다.**
  그 주장이 실제로 성립하는지 재는 케이스다
- CSV에 없는 금리·상품
- 판정과 모순되는 안내
- '어려움'인데 상품 추천

## 결함 주입 — 평가기 자체를 검증한다

**정상 출력이 통과하는 것만으로는 평가기가 작동한다는 증거가 못 된다.**
전 지표 통과와 「평가가 무의미하게 통과만 하는 것」을 구분할 수 없기 때문이다.

각 지표마다 대응하는 결함을 하나씩 주입하고, **주입한 결함이 정확히 그 지표에서만
실패하는지** 확인해라. 다른 지표까지 함께 무너지면 지표가 서로 독립적이지 않다는 뜻이므로
그 사실을 보고해라.

**API 키를 쓰지 마라.** 이 평가는 비용 0이어야 하고 CI에서 돌아야 한다.
