# Codex 작업 지시 — Track B (병렬 트랙)

## 이 저장소에 대해

`loan-suitability-agent` — 금융상담 의사결정 지원 서비스. 현재 FastAPI 재작성 중이며
브랜치는 `feature/decision-support-rebuild`다.

**먼저 읽어라. 내용을 이 프롬프트에 옮겨 적지 않았으니 파일을 직접 열어라.**

| 파일 | 무엇이 있는가 |
|---|---|
| `SPEC.yaml` | 공개 표면 명세. **여기 없는 엔드포인트를 만들면 게이트가 BLOCK한다** |
| `docs/설계결정.md` | ADR 19건. 각 항목에 기각한 대안과 사유가 있다 |
| `docs/리스크_통제_대장.md` | 법적·보안 리스크와 통제 |
| `PROJECT_LOG.md` §구현 상태 | **항목 1에서 확정한 관례.** 이걸 복제해라 |
| `reference/insights/backend-hardening.md` | 하드닝 원칙. **미적용은 결함이고 사유 없이 넘기지 않는다** |

## 절대 규칙

1. **`git commit`·`git push`를 실행하지 마라.** 변경만 남기고 멈춘다.
2. **`SPEC.yaml`에 없는 공개 표면을 만들지 마라.** 필요하면 만들지 말고 보고해라.
3. **코드 주석에 태그·번호를 쓰지 마라.** 원인 → 과정 → 결론을 자연어로 쓴다.
   `[피드백N]`·`[디벨롭]` 같은 표기는 게이트 `L2`가 BLOCK한다.
4. **아래 「내 파일」 목록 밖의 파일을 수정하지 마라.** 다른 트랙이 동시에 작업 중이다.
5. 테스트를 먼저 쓰고 **실패를 확인한 뒤** 구현해라. 새 테스트가 곧바로 통과하면
   이미 구현됐거나 아무것도 검사하지 않는 것이다. 어느 쪽인지 확인 전에 넘어가지 않는다.

# B1. Docker Compose 3-tier + Dockerfile 하드닝

**내 파일:** `docker-compose.yml`(신규) · `Dockerfile` · `.dockerignore`

`docs/설계결정.md`의 **ADR-011**이 계층 구성을 정해뒀다. 그대로 구현해라.

- `ui`(Streamlit) · `app`(FastAPI) · `postgres` 3개 서비스
- **`postgres`는 내부 전용 네트워크에만 두고 호스트 포트를 게시하지 않는다**
- `app`은 호스트에 노출한다(Swagger를 포트폴리오 증거로 쓴다). 이건 의도된 타협이고
  리스크 대장 B3에 사유가 적혀 있다
- non-root 실행과 read-only 루트 파일시스템을 **한 세트로** 적용한다.
  read-only만 켜면 쓰기가 필요한 경로가 드러나므로 그 경로를 개별 허용하는 작업이 함께 온다
- `postgres`에 healthcheck를 걸고 `app`이 그것을 기다리게 한다.
  **기동 순서 의존과 준비 상태 확인은 다른 사실이다** — `depends_on`만으로는 「떠 있는 순서」만 보장된다
- 로그 로테이션을 건다(ADR-016 채택). 여러 서비스에 같은 값을 쓰므로 YAML 앵커로 한 번만 정의한다
- 리소스 상한은 **ADR-016이 조건부 채택**이다. `docker compose config`로 해석 결과를 출력해
  런타임이 실제로 반영하는지 확인해라. 조용히 무시되면 그 사실을 보고하고 채택을 보류해라
- DB 어드민 UI 같은 관리 도구를 기본 기동 대상에 넣지 마라
- 자격증명을 compose 파일에 박지 마라. 인용부호 없는 목록형(`- KEY=값`)도 박은 것과 같다

검증: `python3.11 tools/gate.py .`의 축 `I`(`I1`·`I2`·`I3`·`I5`)에 새 WARN이 없어야 한다.

# B2. CI에 PostgreSQL 추가

**내 파일:** `.github/workflows/ci.yml`

현재 CI는 경량 의존성만 설치해 DB 없는 테스트만 돈다. DB 통합 테스트가 곧 들어오므로
러너에 PostgreSQL을 띄운다.

- `services: postgres`(GitHub Actions 내장)를 쓴다. Testcontainers는 CI에서 쓰지 않는다 —
  도커 안의 도커라 느리고 설정이 까다롭다. **로컬은 compose, CI는 services**이며
  테스트 코드는 `DATABASE_URL` 환경변수로 접속처만 받아 양쪽에서 동일하게 동작해야 한다
- **healthcheck 옵션(`--health-cmd pg_isready`)을 반드시 넣어라.** 없으면 컨테이너가 뜬 것과
  연결을 받을 준비가 된 것을 구분하지 못해 테스트가 간헐적으로 실패한다
- 파이썬은 3.11 유지. 의존성에 DB 드라이버가 추가된다
- `.github/workflows/ci.yml`에 남아 있는 개발 이력용 주석이 있으면 원인 → 과정 → 결론 서술로 정리해라

# B3. Eval 케이스 확대 + 결함 주입

**내 파일:** `loan_agent/eval.py` · `tests/test_eval.py` · 필요 시 픽스처

`docs/평가리포트.md`를 먼저 읽어라. 현재 6지표 5케이스로 30/30이다.
세부기술서(`../01-한화금융/Loan_포트폴리오_디벨롭_세부기술서.md`) §13.2가 확대할 케이스를 나열해뒀다.

**축을 헷갈리지 마라. 이게 이 작업의 핵심이다.**

| 축 | 대상 | 방법 |
|---|---|---|
| **Eval** | 출력 **내용**의 품질 | 녹화된 출력을 규칙으로 채점 |
| **API 통합 테스트** | 실패 **경로**의 처리 | 별도 트랙에서 한다. **여기서 하지 마라** |

판별 기준: 「출력이 있고 그 내용을 채점하는가」면 Eval이다.
「출력이 오지 않거나 형태가 깨졌을 때 시스템이 어떻게 되는가」면 통합 테스트이고 네 담당이 아니다.

따라서 §13.2 목록 중 **LLM 타임아웃·스키마 실패는 네가 다루지 않는다.**
녹화 픽스처로는 타임아웃을 만들 수 없다.

확대할 것 — 경계·적대적 케이스 위주로 10~15건:
- DSR 30%·40% 경계, 한도 정확히 일치 / 1원 초과
- 소득 0, 신용등급 범위 밖, 필수정보 누락
- 모호한 금액 표현(한글 수사 `삼천만원`, 단위 생략 `월 300`)
- **프롬프트 인젝션 입력** — 판정이 불변이고 디스클레이머가 유지되는지 확인
- CSV에 없는 금리·상품, 판정과 모순되는 안내, '어려움'인데 상품 추천

결함 주입은 **각 지표마다 대응하는 결함이 하나씩** 있어야 한다.
정상 출력이 통과하는 것만으로는 평가기가 작동한다는 증거가 못 된다.
주입한 결함이 **정확히 그 지표에서만** 실패하는지 확인해라.

**API 키를 쓰지 마라.** 이 평가는 비용 0이어야 하고 CI에서 돌아야 한다.
