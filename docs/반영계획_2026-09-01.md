## 1. 이 계획을 바꾼 전제

제출 형식이 확인되면서 산출물 구성이 달라졌다. **지원서에 첨부 필드가 없고 링크 하나만 받는다.**

그래서 PDF는 뒤로 미루고 **웹 랜딩 페이지가 포트폴리오 본체**가 된다. 동시에 실패 지점이 하나로 모인다 — 링크가 안 열리거나 열린 화면이 깨져 보이면 대체 경로가 없다.

이 전제가 아래 네 항목의 등급을 올렸다.

| 항목 | 기존 등급 | 변경 | 근거 |
|---|---|---|---|
| 컨테이너 재시작 정책 | 운영 안정성 | **최우선** | 제출 링크가 이 인프라를 가리킨다. 재부팅 후 복구되지 않으면 제출 자체가 실패한다 |
| 다크 모드 대비(`#57`) | 사용성 개선 | **제출 필수** | 심사자가 휴대폰 다크 모드로 열면 검정 배경에 검정 글자다. 그 화면이 제출물의 전부다 |
| 모바일 레이아웃 | 다음 배포 | **제출 필수** | 링크는 휴대폰에서 먼저 열린다 |
| PDF | 산출물 | **보류** | 첨부 경로가 없다. 다른 지원처가 생기면 그때 만든다 |

## 2. 확정 사항

| 논점 | 결정 | 근거 |

| 공개 라이브 입력 | **유지** | 통합의견은 중지를 권고했으나, 그 근거인 잘못된 적격 표시와 고지 부재는 각각 두 줄과 배너 하나로 닫힌다. 기능을 내렸다 재개하는 것보다 거짓 표시를 먼저 없애는 편이 빠르고, 살아 있는 링크 자체가 ADR-031이 배포를 결정한 이유다 |
| 랜딩 페이지 내용 | **전략기획서 §12를 그대로 옮기지 않고 다시 쓴다** | 통합의견의 핵심 지적이 「문서가 구현보다 강하게 설명한다」이다. §12를 복사하면 같은 문제가 웹에서 재발한다 |

## 3. 단계별 실행

### 0단계 — 사고 대응 (사용자, 오늘)

로컬 `.env`의 실제 자격증명이 세 개 LLM 리뷰 세션 컨텍스트에 들어갔다. 저장소 유출은 아니다 — `.env`는 `.gitignore`에 있고 커밋 이력과 문서 어디에도 값이 없다. 문제는 **외부 서비스 세 곳으로 전송된 것**이다.

1. OpenAI 키 폐기·재발급, 사용량 확인
2. `POSTGRES_PASSWORD` 변경 (로컬·EC2 양쪽)
3. ~~EC2 `.env` 확인~~ — **완료(2026-09-01).** `POSTGRES_USER`·`POSTGRES_PASSWORD`·`POSTGRES_DB` 셋뿐이고 `OPENAI_API_KEY`는 없다. 권한 600. **ADR-031 §31.3은 실제로 지켜지고 있으므로 별도 판정이 필요 없다**

자격증명 발급과 입력은 사람이 한다.

확인 과정에서 값을 읽지 않고 변수명과 길이만 조회했다. 자격증명이 세 개 세션에 들어간 것이 이번 사고의 내용인데 확인이 같은 일을 반복하면 수습이 아니라 확대가 된다.

같은 접속에서 운영 상태를 함께 봤고 **결함 두 건이 새로 나왔다** — `#60`(서버가 병합된 브랜치에 고정) · `#61`(재시작 정책 부재 실측). 둘 다 1단계로 들어간다.

### 1단계 — 제출 인프라 (1일)

| # | 조치 | 검증 |
|---|---|---|
| **1-0** | **서버를 `main`으로 전환**(`#60`). 배포절차서 §6의 `clone -b feature/decision-support-rebuild`도 함께 정정 | `git rev-parse --abbrev-ref HEAD` → `main` · `git rev-list --count HEAD..origin/main` → 0 |
| 1-1 | `docker-compose.prod.yml`에서 `ui`·`app`·`postgres`에 `restart: unless-stopped`(`#61`). `migrate`는 제외 — 한 번 실행하고 끝나는 서비스라 `"no"`가 옳다 | EC2 재부팅 후 네 서비스가 스스로 healthy에 도달하는 것을 실측 |
| 1-2 | Caddyfile에 정적 서빙 블록 추가. 앱 컨테이너를 거치지 않는다 | Streamlit을 내린 상태에서 랜딩 페이지가 열리는 것 확인 |
| 1-3 | `.streamlit/config.toml`에 `[theme] base = "light"` | 브라우저 다크 모드에서 본문 대비 확인 |
| 1-4 | sidebar 강제 고정·collapse 버튼 제거를 desktop media query 안으로 한정 | 375~390px 폭에서 입력·결과 도달 가능 |

1-2가 중요한 이유는 장애 격리다. 랜딩 페이지를 `ui` 컨테이너가 서빙하면 Streamlit이 죽을 때 포트폴리오가 함께 사라진다.

1-3과 1-4는 **최소 동작을 확보하는 바닥**이다. 각각 한 줄과 미디어 쿼리 한 벌이며, 뒤의 스타일 정비가 밀려도 이 바닥은 남는다. 스타일을 먼저 손대고 바닥을 나중에 깔면 작업이 밀릴 때 제출물이 깨진 채로 남는다.

### 2단계 — 화면과 사실의 일치 (0.5일)

포트폴리오에서 가장 위험한 것은 버그가 아니라 화면이 사실과 다른 것이다. 심사자가 그것을 잡으면 나머지 주장의 신뢰가 함께 무너진다.

| # | 대상 | 현재 | 조치 |
|---|---|---|---|
| 2-1 | 히어로 문구 | "3개 Agent(파싱 → 심사 → 안내)가 순차 협업" | 세 부분 모두 사실과 다르다. 정의된 Agent는 둘이고, 라이브 경로에서 실행되는 것은 안내가 하나이며, 심사는 Agent가 아니라 결정적 함수다. 실제 구조를 쓴다 |
| 2-2 | 적격 상품 목록(`#58`) | 상위 3건을 전체 목록인 양 표시 | 「추천 상위 3건」으로 라벨 정정. 부적격 사유가 빈 경우 "이 경로에서는 제공되지 않음"을 명시해 정보 없음과 해당 없음을 구분 |
| 2-3 | `USER_GUIDE.md` | 저장소 루트에 하네스 사용설명서 35KB | 제거. 대출 서비스와 무관하고 내부 도구 구조를 공개한다. 원본은 `~/.harness-src`에 있다 |

### 3단계 — 고지와 서버 통제 (1일)

| # | 조치 | 근거 |
|---|---|---|
| 3-1 | 입력 폼 위에 데이터 처리 고지 배너 — 실제 개인정보 입력 금지, 합성 상품 데이터, 저장 항목, 원문 미저장 | `docs/리스크_통제_대장.md`가 이미 약속한 통제인데 화면에 렌더되지 않는다. 새 판단이 아니라 누락 보완이다 |
| 3-2 | `ui` 서비스에서 `env_file` 제거, 필요한 값만 `environment`로 전달 | UI는 DB에 접속하지 않는데 `env_file`이 `.env` 전체를 넘겨 `POSTGRES_PASSWORD`가 컨테이너 환경에 들어간다 |
| 3-3 | body 크기 상한과 Content-Type 검사 미들웨어(413·415) | `SPEC.yaml:70-72`가 셋을 약속하고 "enforced by the API itself"라고 명시했는데 `errors.py`에 제목 문자열만 있고 raise하는 곳이 없다 |
| 3-4 | 인메모리 요청 상한(429) | 단일 인스턴스이므로 프로세스 내 카운터로 충분하다. 분산 저장소는 지금 구조에 필요 없다 |

413·415·429는 명세를 코드에 맞추는 것이 아니라 **코드를 명세에 맞추는 방향**으로 닫는다. 명세를 줄이면 약속을 없애는 설계 변경이 되어 `/design` 복귀가 필요하다.

### 4단계 — UI 스타일 정비 (1.5일)

기능 개선(UX)은 마감에 맞지 않지만 **보이는 수준은 별개 문제**다. 심사자가 링크를 열었을 때 첫 인상이 결과물의 나머지를 채색한다.

**범위를 시각 표현으로 한정한다.** 상호작용 흐름·상태 관리·비동기 구조는 건드리지 않는다. 그 둘을 섞으면 회귀 위험이 커지고 영상 재촬영이 필요해진다.

| # | 대상 | 조치 |
|---|---|---|
| 4-1 | 디자인 토큰 | `static/apple.css`의 색·간격·타이포를 토큰으로 정리한다. 지금은 값이 209줄에 흩어져 있어 한 곳을 바꾸면 다른 곳이 어긋난다 |
| 4-2 | 타이포그래피 | 제목·본문·캡션의 크기 단계와 행간을 다시 잡는다. 정보 위계가 시각적으로 드러나야 한다 |
| 4-3 | 간격 체계 | 카드·섹션·폼 요소의 여백을 한 배수로 통일한다 |
| 4-4 | 결과 화면 | 판정 배지, 적격 상품 표, 안내문 블록의 시각 위계. **이 화면이 영상의 절반을 차지한다** |
| 4-5 | 랜딩 페이지 공용화 | 같은 토큰을 랜딩 페이지가 재사용하도록 분리한다. 두 화면이 한 디자인 언어를 쓰면 자체 호스팅이라는 사실이 시각적으로도 드러난다 |

4-5가 다음 단계의 비용을 줄인다. 랜딩 페이지를 처음부터 새 스타일로 그리면 이 단계와 5단계가 한 번에 끝난다.

**이 단계를 3단계 뒤, 영상 앞에 두는 이유는 재촬영을 막기 위해서다.** 스타일을 고친 뒤 찍어야 한 번에 끝난다.

### 5단계 — 랜딩 페이지와 영상 (3.5일)

`#55`(진행 표시 없음)를 여기 앞에 붙인다. 대기 화면이 영상에 그대로 찍히기 때문이다. 4단계에서 스타일 토큰을 공용화해 두었으므로 랜딩 페이지는 처음부터 새 스타일로 그린다.

**랜딩 페이지 구성 — 실행되는 것만 주장한다**

1. 한 줄 요약과 관통 논리
2. 무엇이 결정적이고 무엇이 LLM인가 — 경계를 그림 하나로
3. **실측 증거** — `#52`(LLM 파서가 「부채 200만원」을 20만원으로 읽었고 규칙 파서와의 대조가 잡았다), `#56`(규칙 파서가 콤마 금액을 만 배로 읽었다). 두 사례가 교차검증 설계의 값어치를 주장이 아니라 데이터로 보여준다
4. 영상 데모 인라인 + 정지 이미지
5. 라이브 데모 링크(`loan.gwang.dev`), 저장소 링크
6. **검증된 범위와 한계** — 운영에 워커·서버 키가 없어 비동기 경로가 공개 데모에서 돌지 않는다는 것, 적격 목록이 상위 3건이라는 것, 미검증 항목
7. 규제 판단 — 준수 주장이 아니라 적용 조건 밖으로 설계했다는 서술

6번이 이 페이지에서 가장 중요하다. 통합의견이 지적한 결함의 공통 원인이 「약속과 실행의 괴리」였으므로, **못 하는 것을 먼저 적는 페이지**가 그 지적에 대한 구조적 응답이 된다. 금융 IT 인수 관점에서 한계를 아는 지원자가 한계를 모르는 지원자보다 신뢰된다.

### 단일 실패점 보완

제출 링크가 하나뿐이라 도메인이 막히거나 인스턴스가 죽으면 대체 경로가 없다. 비용이 거의 없는 보험 둘을 함께 둔다.

1. **저장소 README를 완전한 대체 매체로 만든다.** 랜딩 페이지와 같은 내용을 담고 서로를 가리키게 하면 심사자가 어느 쪽에 도달하든 이야기가 완결된다. 내용을 공유하므로 추가 비용이 작다
2. **가동 감시** — 마감 전후 2주만이라도 외부 모니터로 다운을 알림받는다

| 항목 | 판단 | 재검토 조건 |
|---|---|---|
| `core.py` 분할(`#38`) | 하지 않는다. 355줄이고 「LLM 미개입」이라는 경계가 파일 단위로 이미 드러나 있다 | 500줄 초과, 또는 하위 영역의 변경 주기가 갈릴 때 |
| 두 파서 UI 연결 | 하지 않는다. ADR-029의 값어치는 `#52`가 데이터로 증명했다. 연결하려면 구조화 스키마·값 범위·프롬프트 주입 시험을 함께 넣어야 해서 마감에 맞지 않는다 | 다음 기능 배포 |
| 내부 API 인증·mTLS | 단일 노드 데모에 과도하다 | `app` 외부 노출, UI 다중 인스턴스, 실제 사용자 식별 도입 |
| Multi-AZ·IAM·복구 훈련 | 애플리케이션 결함이 아니라 인프라 조직 소유 항목이다 | 실제 고객 대상 운영 인수 |
| 의존성 고정·SBOM | 시간이 남으면 `pip freeze` 고정만 먼저 | 다음 기능 배포 |
| Chroma 취약점 | 미사용 전이 의존성이고 해당 엔드포인트를 실행하지 않아 도달 경로가 없다 | Chroma 관련 기능을 켜는 순간 |
| `#59` 파서 후행 콤마 | 정상 입력에서 재현되지 않는 엣지다 | 파서를 다시 손댈 때 함께 |
| 커밋 이력의 협업 표기 | 초기 20커밋(2026-07-27)에 남아 있고 규칙은 그보다 한 달 뒤에 생겼다. 걷어내려면 79커밋 해시가 전부 바뀌어 피드백 대장의 대응 기록이 무효가 된다 | 없음. 유지하고 방어 논리로 쓴다 |

## 6. 완료 판정 기준

랜딩 페이지 공개 전에 아래가 모두 증거로 남아야 한다.

- 자격증명 폐기·재발급이 끝났다
- `ui` 컨테이너 환경에 DB 비밀번호가 없다
- EC2 재부팅 후 `ui`·`app`·`postgres`가 스스로 복구된다
- Streamlit을 내린 상태에서도 랜딩 페이지가 열린다
- 375~390px 폭에서 입력과 결과에 도달할 수 있다
- 브라우저 다크 모드에서 본문이 읽힌다
- 화면·README·랜딩 페이지가 실제 실행 경로를 그대로 설명한다 — Agent 수, 파서 구성, 적격 목록 범위, 키 처리
- 413·415·429가 자동 테스트에서 실제로 발생한다
- 데이터 처리 고지가 제출 전에 보인다

## 7. 남은 불확실성

추측으로 통과 처리하지 않는다.

- EC2 `.env`의 실제 내용 (SSH 확인 필요, 승인 대상)
- AWS 보안그룹 전체 source, NACL, IPv6, IAM, IMDS
- 실기기(iOS·Android)와 Safari·Firefox 렌더링
- 백업·복구 실효성
- `gwang.dev`가 대상 조직 네트워크에서 열리는지 — 확인할 방법이 없으므로 README 대체 매체로 보완한다
