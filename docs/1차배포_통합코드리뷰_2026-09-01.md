## 1. 핵심 결론

**현 상태는 금융회사 운영 서비스 기준으로 승인 불가(NO-GO)이며, 공개 포트폴리오 데모도 P0 조치 전까지는 입력 기능을 중지하고 녹화 데모만 제공하는 편이 안전하다.**

확인된 외부 경계만 보면 Caddy 이외의 FastAPI·PostgreSQL 포트로 직접 우회 진입하는 경로는 재현되지 않았다. 그러나 다음 이유로 “3-tier 우회 지점을 전부 막았다”고 결론 내릴 수 없다.

- AWS 보안그룹·NACL·IPv6·IAM·IMDS·EBS·백업 설정은 AWS 자격증명 부재로 확인하지 못했다.
- 내부 FastAPI는 인증·사용자 소유권 검사가 없고, UI·Caddy·app이 같은 frontend 네트워크를 사용한다.
- 공개 UI 프로세스에 불필요한 DB 비밀번호가 실제 운영 환경에서 주입돼 있다.
- 명세가 약속한 본문 크기·Content-Type·서버 측 rate limit이 구현되지 않았다.
- 사용자에게 실제와 다른 적격·부적격 결과가 표시될 수 있고, Eval 품질 게이트도 한국어 단위 금액을 놓친다.
- 실제 금융정보 입력 금지·보유기간·삭제 정책 고지가 없는데 구조화 입력은 DB에 저장된다.

직접 악용 가능한 Critical 취약점은 이번 범위에서 확인하지 못했다. 다만 별도의 보안 사고성 조치 1건과 High 9건, Medium 16건, Low 4건을 확인했다.

## 2. 판정 기준과 증거 구분

- **확인:** 코드, 테스트, 라이브 HTTP·브라우저, 실행 중 컨테이너 또는 읽기 전용 SSH로 직접 확인했다.
- **추론:** 확인된 구조로부터 재현 가능한 장애·공격 결과를 합리적으로 도출했지만 실제 장애를 발생시키지는 않았다.
- **미검증:** 권한·실기기·외부 시스템이 필요해 이번 검토에서 확인하지 못했다.

## 4. 즉시 사고 대응 항목

### INC-01. 검토 과정에서 로컬 OpenAI 키가 기밀 취급을 상실함

- 상태: **확인**
- 증거: 로컬 Compose 확장 출력이 실제 형식의 OpenAI 키를 환경변수 값으로 포함했다. 키 값은 이 문서와 로그 요약에 반복하지 않는다. 로컬 .env는 Git에서 ignore되고 추적 이력에서는 실제 키를 찾지 못했지만 파일 권한은 0644였다.
- 영향: 출력에 접근 가능한 주체를 완전히 열거할 수 없으므로 해당 키는 유출된 것으로 취급해야 한다.
- 즉시 조치: 해당 키를 OpenAI 콘솔에서 폐기·회전하고 사용량을 점검한다. 새 키는 .env 전체 주입 대신 최소 권한 secret 경로로 전달하며 로컬 비밀 파일 권한을 0600으로 제한한다.

## 5. 잘된 점

### 5.1 코드 품질

- [core.py](../loan_agent/core.py)는 결정적 판정을 LLM 경로에서 분리한다. 같은 구조화 입력의 승인·상담필요·어려움 판정은 LLM이 바꾸지 않는다.
- [assessments.py](../loan_agent/api/assessments.py)는 Idempotency-Key, request hash, DB UNIQUE 제약을 함께 사용한다. 동시 요청 경쟁 테스트도 있다.
- 짧은 DB 트랜잭션, 제한된 connection pool, statement timeout, FOR UPDATE SKIP LOCKED의 사용 목적이 분명하다.
- Alembic을 schema source of truth로 사용하고 readiness에서 migration head까지 확인한다.
- 테스트가 단순 happy path를 넘어 DB 제약, 멱등 경쟁, worker claim 경쟁, Eval 결함 주입을 포함한다.
- Git 이력은 기능·장애 단위 커밋을 상당 부분 보존해 문제 맥락을 추적할 수 있다.

### 5.2 보안

- SQLAlchemy ORM과 고정 SQL을 사용하며 사용자 입력을 SQL 문자열에 연결하는 경로를 찾지 못했다.
- 사용자 제어 shell 명령, 파일 업로드, 파일 경로, 임의 URL fetch가 없어 command injection·path traversal·SSRF의 직접 경로를 찾지 못했다.
- 자연어 원문은 DB 모델에 저장하지 않고 validation error 응답에서도 원 입력을 제거한다.
- 사용자·LLM 텍스트는 기본 안전 렌더링을 사용한다. unsafe_allow_html은 확인한 범위에서 정적 HTML 또는 내부 enum에만 사용돼 확인된 XSS 경로는 없다.
- CORS를 광범위하게 허용하지 않았고 라이브 Origin 변조 요청에도 Access-Control-Allow-Origin이 없었다.
- app·ui·postgres는 non-root·read-only로 실행되고 DB network는 internal이다.
- HTTPS, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy와 TLS 1.2·1.3을 확인했다.
- 안내문에는 disclaimer를 코드로 강제하고 Eval 미통과 안내문은 공개하지 않는다.

### 5.3 서비스 품질

- API 장애나 LLM 실패가 결정적 판정 자체를 없애지 않는다.
- 키 없는 녹화 데모가 있어 토큰 없이 주요 결과를 볼 수 있다.
- DSR, 금액, 가정값을 비교적 읽기 좋은 형식으로 표시한다.
- 라이브 데스크톱 라이트 환경에서 기본 페이지 로드와 주요 위젯 렌더는 성공했고 브라우저 console error는 없었다.

## 6. High 발견사항

### H-01. 전체 적격·부적격 결과가 API/UI 경계에서 손실돼 거짓 설명이 표시됨

- 교차 영역: 코드 품질 · 서비스 품질 · 금융 설명 책임
- 상태: **확인**
- 증거: [core.py L209-L210](../loan_agent/core.py#L209)는 전체 적격 목록과 상품별 부적격 사유를 계산하지만 [decision.py L71-L79](../loan_agent/decision.py#L71)는 상위 추천 3개만 저장한다. [app.py L372-L401](../loan_agent/app.py#L372)은 추천 3개를 전체 적격상품으로 바꾸고 부적격사유를 빈 dict로 만든다. [app.py L159-L163](../loan_agent/app.py#L159)은 빈 사유를 “모든 상품이 조건을 충족합니다”로 표시한다.
- 재현: 대표 승인 입력에서 도메인 결과는 적격 8개·부적격 14개였지만 저장 추천은 3개였다.
- 영향: 고객이 적격 상품 범위와 탈락 사유를 사실과 다르게 이해한다. 녹화 데모는 core를 다시 계산해 정상으로 보여 라이브 결함을 가린다.
- 조치: 전체 상품 eligibility와 reason code를 별도 persistence/API response model로 보존한다. 수정 전에는 라이브 “부적격 사유”를 숨기고 “정보 없음”으로 표시한다. 도메인 결과와 라이브·녹화 렌더의 동등성 계약 테스트를 추가한다.

### H-02. 명세의 413·415·429와 전역 자원 통제가 실제 서버에 없음

- 교차 영역: 보안 · FastAPI 활용 · 서비스 가용성 · 비용
- 상태: **확인**
- 증거: [SPEC.yaml L65-L99](../SPEC.yaml#L65)은 본문 크기, Content-Type, rate limit을 API가 강제한다고 기술하지만 [api/__init__.py](../loan_agent/api/__init__.py)에 해당 middleware가 없다. TestClient probe에서 text/plain, 10KB 초과 field, 1MiB 초과 body는 각각 계약상의 415·413이 아니라 422였다. UI 제한은 [app.py L434-L565](../loan_agent/app.py#L434)의 Streamlit session state뿐이다.
- 영향: 새 브라우저 세션이나 내부 API 직접 호출로 제한을 초기화할 수 있다. DB 행 무한 생성, request body·connection·thread pool·LLM 동시 호출 고갈이 가능하다.
- 조치: Caddy와 FastAPI 양쪽에 header/body 크기 제한을 두고, 검증된 client/session 식별자를 기반으로 global·IP·session rate limit을 구현한다. LLM semaphore·queue depth·전체 timeout을 추가하고 413·415·429 통합 테스트를 배포 차단 조건으로 둔다.

### H-03. 실제 금융정보 입력을 막지 않으면서 구조화 값은 기한 없이 저장됨

- 교차 영역: 개인정보 · 서비스 신뢰 · 데이터 수명주기
- 상태: **확인**
- 증거: README만 합성 데이터라고 설명한다. 공개 [app.py L507-L528](../loan_agent/app.py#L507)은 고객 상담 내용, 월소득, 부채, 신용등급, 희망금액을 입력받지만 실제 정보 입력 금지·저장 항목·보유기간·삭제 정책을 입력 전에 표시하지 않는다. [models.py L68-L73](../loan_agent/db/models.py#L68)는 구조화 금융정보를 DB에 저장하며 TTL·삭제 API·retention job이 없다.
- 영향: 방문자가 실제 값을 넣으면 의도한 “합성 데이터 전용” 범위를 벗어난다. 원문 미저장은 장점이지만 구조화 금융정보도 민감할 수 있다.
- 조치: 정책 확정 전에는 라이브 입력을 중지하고 녹화 예시만 제공한다. 데모를 유지하려면 입력 전 강한 합성 전용 고지와 동의, 예시 선택형 입력, 짧은 TTL, 삭제·파기 검증을 구현한다. 실데이터 서비스로 전환하려면 별도 개인정보·보안·법무 심사를 거친다.

### H-04. 공개 UI에 .env 전체가 주입돼 운영 DB 비밀번호까지 노출 범위에 포함됨

- 교차 영역: 보안 · AWS/컨테이너 구성 · 최소 권한
- 상태: **확인**
- 증거: [docker-compose.yml L20-L24](../docker-compose.yml#L20)의 ui env_file이 .env 전체를 전달한다. 실행 중 운영 UI에서 OpenAI 키는 없었지만 PostgreSQL 비밀번호는 존재했다. Docker 공식 문서도 env_file의 변수들이 컨테이너에 전달된다고 명시한다.
- 영향: Streamlit 또는 transitive dependency가 침해되면 UI에 불필요한 DB 자격증명까지 함께 노출된다. .env에 서버 OpenAI 키를 넣는 환경에서는 피해 범위가 더 커진다.
- 조치: UI의 env_file을 제거하고 API_BASE_URL 등 비밀이 아닌 최소 변수만 명시한다. app·migrate·worker별 secret을 분리하고 AWS Secrets Manager 또는 SSM Parameter Store를 사용한다. migration owner와 runtime DB role도 분리한다.
- 참고: [Docker Compose services / env_file](https://docs.docker.com/reference/compose-file/services/#env_file)

- 상태: **확인**
- 증거: [eval.py L56-L58](../loan_agent/eval.py#L56)의 정규식은 1,000,000원 형태만 인식하고 9억원, 500만원, 2천만 원을 보지 못한다. [worker.py L228-L231](../loan_agent/worker.py#L228)은 실제 파싱 결과가 없는데 파싱정확도를 True로 덮어쓴다.
- 재현: 허용 근거에 없는 “최대 한도 9억원”을 넣은 안내문이 6개 지표를 모두 통과했다.
- 영향: README가 주장하는 90점 Eval과 “환각 0” 품질 게이트보다 실제 통제가 약하다.
- 조치: 한국어 수사·단위를 원 단위로 정규화하고 구조화 출력의 amount/value/unit/source를 검증한다. 적용 불가능한 파싱 지표는 True가 아니라 N/A로 분리한다. 억·만·천만·공백·소수 조합의 mutation test를 추가한다.

### H-06. 화면의 3-Agent·이중 파서·키 보관 설명이 실제 실행 경로와 다름

## 7. Medium 발견사항

### M-01. 내부 API에 인증·사용자 소유권·서비스 간 인증이 없음

- 상태: **확인**
- 증거: [assessments.py L247-L286](../loan_agent/api/assessments.py#L247)와 [explanations.py L71-L121](../loan_agent/api/explanations.py#L71)은 목록·상세·재생성 경로에 사용자 인증 또는 assessment owner 검사를 두지 않는다.
- 위험: 현재 외부 프록시가 FastAPI를 공개하지 않아 직접 IDOR는 재현되지 않았다. 그러나 UI·Caddy 침해, override port 노출 또는 향후 routing 변경 시 모든 심사 조회·변경이 가능해진다.
- 조치: UI→app workload credential과 요청별 opaque session/owner binding을 도입한다. 불필요한 목록 API는 제거하거나 관리 plane으로 분리한다.

### M-02. 내부 네트워크가 평면적이고 Caddy hardening이 다른 컨테이너보다 약함

- 상태: **확인**
- 증거: Caddy·UI·app이 같은 frontend network에 있어 Caddy는 app에 직접 도달할 수 있다. UI→app과 app→DB는 평문이다. Caddy는 root·writable filesystem이고 app·ui의 read-only/non-root 기준과 다르다.
- 위험: edge 또는 UI 침해가 service credential 없이 다음 tier로 확장될 수 있고 Caddy 침해의 호스트·인증서 영향이 커진다.
- 조치: edge-ui, ui-api, api-db network를 분리하고 workload 인증 또는 mTLS를 검토한다. Caddy non-root·read-only·cap_drop·no-new-privileges·resource limit을 적용한다.

### M-03. 방문자 LLM 실행이 최대 200초 이상 동기 HTTP 요청을 점유함

- 상태: **확인**
- 증거: [explanations.py L71-L90](../loan_agent/api/explanations.py#L71), [worker.py L325-L329](../loan_agent/worker.py#L325), [app.py L569-L575](../loan_agent/app.py#L569)이 한 요청에서 provider 호출 완료까지 기다린다.
- 위험: 소수의 병렬 요청으로 Streamlit session, Uvicorn thread pool, DB/API connection, 2 vCPU·2GiB EC2 자원이 장시간 점유될 수 있다.
- 조치: visitor key도 enqueue → 202 → polling/SSE 구조로 전환한다. 전환 전에는 global semaphore, queue upper bound, circuit breaker와 짧은 request timeout을 둔다.

### M-04. stale worker 재클레임에 fencing token이 없음

- 상태: **확인된 구조 + 장애 결과는 추론**
- 증거: [worker.py L92-L110](../loan_agent/worker.py#L92)은 동일 run ID를 PENDING으로 되돌리고 [worker.py L235-L278](../loan_agent/worker.py#L235)은 현재 claim owner인지 확인하지 않고 완료한다.

- 조치: claim마다 attempt_no 또는 lease/fencing token을 증가시키고 최신 token의 조건부 UPDATE만 완료를 허용한다. 완료 순서를 뒤집는 concurrency integration test를 추가한다.

- 위험: app 침해 시 schema 변경 권한까지 확대될 수 있고, 고객 이의·장애 조사 시 누가 어떤 상태 전이를 만들었는지 재구성하기 어렵다.
- 조치: owner/migrator/runtime/read-only role을 분리한다. request correlation ID와 claim attempt를 append-only audit에 남긴다. EBS·snapshot 암호화, 자동 backup, restore RTO/RPO rehearsal를 증거로 남긴다.

### M-15. 배포 명령·branch 문서가 충돌해 단일 진입점이 사람의 실수에 의존함

- 상태: **확인**
- 증거: [docker-compose.override.yml](../docker-compose.override.yml)은 일반 docker compose 실행 시 8000·8501을 host에 게시한다. [docs/배포계획.md](./배포계획.md)의 오래된 일반 명령과 [docs/배포절차.md L214-L218](./배포절차.md#L214)의 feature branch clone이 현재 main 기준과 충돌한다. 실제 운영도 해당 feature branch에 남아 있다.
- 위험: 운영자가 잘못된 명령을 쓰면 Caddy 단일 진입점 불변식이 깨지고 최신 patch를 놓칠 수 있다.
- 조치: release tag/SHA와 운영 전용 deploy script 한 개만 허용한다. rendered Compose에서 Caddy 이외 published port가 있으면 배포를 중단하는 자동 검사를 둔다.

### M-16. 장시간 실행의 진행·오류 복구와 입력 의미가 부족함

- 상태: **확인**
- 증거: [app.py L69-L79](../loan_agent/app.py#L69)의 WAIT_TIPS와 [L117-L129](../loan_agent/app.py#L117)의 friendly error mapper는 사용되지 않는다. [apple.css L22-L30](../loan_agent/static/apple.css#L22)은 status widget을 숨기고 [app.py L598-L599](../loan_agent/app.py#L598)은 대부분의 오류를 한 문장으로 합친다. 월소득의 세전/세후, 부채 잔액, 신용등급 기준도 field help가 없다.
- 위험: 최대 210초 동안 사용자는 실행 여부·비용·재시도 가능성을 알기 어렵고, 같은 숫자를 다른 의미로 입력할 수 있다.
- 조치: 단계·최대시간·assessment ID·취소/재조회 UX를 제공하고 401·429·503·network error를 구분한다. 월소득·부채·등급·담보의 기준일과 계산 가정을 입력 옆에 명시한다.

## 8. Low 발견사항

### L-01. CSP·Permissions-Policy와 edge fingerprint 최소화가 없음

- 상태: **확인**
- 증거: [Caddyfile](../Caddyfile)의 기존 보안 header는 유효하지만 CSP와 Permissions-Policy가 없고 라이브 응답은 Via: 1.1 Caddy를 노출했다.
- 조치: Streamlit WebSocket·inline style 호환성을 검증한 CSP부터 report-only로 적용하고 불필요한 browser capability를 제한한다.

### L-02. 대형 UI module, dead helper, 오래된 주석이 유지보수 비용을 높임

- 상태: **확인**
- 증거: app.py가 HTTP client, session state, domain adapter, UI rendering, error mapping을 한 파일에서 담당한다. 미사용 WAIT_TIPS·friendly error와 삭제된 notebook/예전 LLM 구조를 설명하는 [core.py](../loan_agent/core.py) 주석이 남아 있다.
- 조치: api_client, view_model, state, component 단위로 분리하고 역사적 설명은 ADR/개발이력으로 이동한다. 주석은 현재 불변식과 의도를 설명하도록 정리한다.

### L-03. 사소한 운영 계약·개발 환경 불일치가 남음

- 상태: **확인**
- 증거: versioned API와 unversioned health의 혼용, 일부 Dockerfile EXPOSE와 실제 service port의 불일치, 로컬 기본 python3 3.14와 프로젝트 의존성이 설치된 Python 3.11의 차이가 있다. Starlette TestClient의 httpx app shortcut deprecation warning도 발생했다.
- 조치: 지원 Python 버전과 실행 command를 명시하고 health/port convention, deprecated test client 사용을 정리한다.

### L-04. 금액 parser가 문장부호의 후행 comma를 원 단위 표기로 오인함

- 상태: **확인**
- 증거: [core.py L234-L255](../loan_agent/core.py#L234)는 숫자 match에 후행 comma를 허용하고 comma가 하나라도 있으면 원 단위 전체 금액으로 판단한다. “월 3, 신용등급 1등급” probe에서 월소득이 관행상 3만원이 아니라 3원으로 파싱됐다.
- 영향: 정상적인 금융 금액 입력 가능성은 낮아 Low로 분류하지만, 주석이 방어한다고 설명한 문장부호 case를 실제 정규식은 막지 못한다.
- 조치: 단위 추론 전에 trailing punctuation을 제거하고 해당 문장을 parser regression case에 추가한다.

## 13. 재배포 승인 조건

다음 조건을 모두 충족해야 공개 입력 기능 재배포를 승인할 수 있다.

- 사고 대응 키가 폐기·회전됐고 새 키가 UI container에 존재하지 않는다.
- High 이슈 9건이 모두 해소되거나 서비스 범위 축소로 도달 불가능함이 테스트로 증명된다.

- 9억원·500만원·2천만 원 등 한국어 단위의 근거 없는 수치가 Eval에서 실패한다.

- 모바일 390px, desktop dark, keyboard, WCAG AA 대비가 자동·수동 검증을 통과한다.
- app·ui·postgres가 EC2 reboot 후 자동 복구된다.
- dependency advisory를 제거하거나 reachability·보완통제·만료일을 승인 기록으로 남긴다.
- release tag/SHA와 rendered Compose 검사가 단일 배포 절차에 포함된다.

## 14. 미검증 범위와 결론의 한계

- AWS 보안그룹 전체 source CIDR, NACL, IPv6, outbound rule
- EC2 instance profile/IAM, IMDSv2, CloudTrail, GuardDuty, EBS/snapshot encryption
- 다른 외부 source IP에서의 SSH 차단
- 운영 access/application log의 실제 redaction과 보존기간
- backup·restore 실효성, multi-AZ/복구 시간
- iOS·Android 실기기, Safari·Firefox, VoiceOver·TalkBack, 200% 확대
- 실 OpenAI provider의 429·quota·장시간 latency·response loss
- 실제 부하·침투 시험, container capability·seccomp/AppArmor, 전체 image CVE scan

따라서 이번 결론은 “현재 확인 범위에서 외부 backend 직접 우회는 재현되지 않았다”까지다. “모든 우회 경로가 차단됐다”는 보증은 아니다. 금융회사 수준의 운영 승인에는 위 미검증 항목의 IaC·설정 export·복구 시험·침투 시험 증거가 추가로 필요하다.
