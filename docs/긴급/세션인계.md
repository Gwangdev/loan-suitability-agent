- **데이터 모델 동결** — 인덱스 마이그레이션 2개는 절대 병합하지 않는다. `0003`은 별개라 정상

## 5. 이 프로젝트에서 배운 것 — 다음 판단의 근거

**결함을 가장 많이 잡은 것은 읽기가 아니라 실행이었다.**

| 방법 | 잡은 결함 |
|---|---|
| `/code-review` (읽기) | 7건 |
| `docker compose up` | **2건 — 둘 다 기동 차단.** 스택은 그때까지 한 번도 뜬 적이 없었다 |
| 오너 키로 1회 실행 | 4건 |
| **배포 후 실사용** | **2건 — 화면을 죽이는 `KeyError`와 만 배 파싱 오차** |

`#47`(alpine uid ≠ 999)·`#48`(이미지에 마이그레이션 없음)·`#49`(리팩토링이 빠뜨린 임포트)는 **읽어서는 원리상 나올 수 없는 종류**다. 이것이 리뷰를 배포 뒤로 미룬 판단의 근거이고, 결과가 그 판단을 지지했다.

**포트폴리오에서 인용할 사례 두 개**

- **`#52`** — 녹화 데모를 만들 때 **LLM 파서가 「부채 200만원」을 200,000원으로** 읽었다. 규칙 파서가 옳게 읽어 불일치로 걸렸다. **ADR-029(두 파서 교차검증)의 값어치를 말이 아니라 데이터로 보여준다.** 근거는 `demo_fixtures.json`의 `parse_check`
- **`#56`** — **규칙 파서가 「3,000,000」을 300억으로** 읽었다. 단위 미기재 기본값(만원)이 콤마 찍힌 전체 금액에까지 적용된 탓이다. **판정 로직을 아무리 결정적으로 만들어도 입력이 틀리면 소용없다**는 사례
