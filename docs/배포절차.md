## 0. 먼저 — 코드를 원격에 올린다

**서버는 GitHub에서 코드를 가져온다. 그런데 이 브랜치는 아직 원격에 없다.** `main`은 재구축 이전 코드(2026-07-27)다.

```bash
git push -u origin feature/decision-support-rebuild
```

**`main`에 병합하지 않는다 — 아직은.** 지금 `main`을 바꾸면 Streamlit Cloud에서 돌던 기존 공개 데모가 먼저 죽는다. **대체품이 동작하는 것을 확인한 뒤에 병합한다.** 순서를 뒤집으면 배포가 실패했을 때 돌아갈 곳이 없다.

**공개 전 점검은 끝났다:** `.env` 미추적·이력에도 없음 · 게이트 `X1`·`X2`·`X3`·`L1`·`L2` 무발생 · `COMMIT READY`.

## 1. EC2 인스턴스 생성 (콘솔)

`EC2 → 인스턴스 → 인스턴스 시작`

| 항목 | 값 | 이유 |
|---|---|---|
| 이름 | `loan-demo` | |
| AMI | **Amazon Linux 2023 (arm64)** | Docker 설치가 가장 간단하다 |
| 인스턴스 유형 | **`t4g.small`** | 2 vCPU / 2 GiB. ARM이라 같은 성능에 싸다 |
| 키 페어 | **새로 생성** · 이름 `loan-demo` · 유형 **ED25519** · 형식 **`.pem`** | **다시 받을 수 없다.** 잃으면 접속 불가 |
| 스토리지 | **gp3 20 GiB** | 이미지·DB·로그 |
| 리전 | **ap-northeast-2 (서울)** | 지연시간 |

**네트워크 설정**

| 항목 | 값 |
|---|---|
| VPC · 서브넷 | **기본값** 그대로. AWS가 가용 영역을 고른다 |
| 퍼블릭 IP 자동 할당 | **활성화** |
| 방화벽 | **새 보안 그룹 생성** · 이름 `loan-demo-sg` |
| 인바운드 | 지금은 **SSH(22) → 내 IP** 만. 80·443은 §3에서 추가한다 |

퍼블릭 IP 자동 할당을 켜면 탄력적 IP를 붙이기 전에도 접속할 수 있다. §2에서 탄력적 IP를 연결하면 자동 할당분은 반납되고 대체되므로 낭비가 아니다.

**파일 시스템 — 아무것도 추가하지 않는다.**

이 항목은 EFS·FSx(공유 파일 시스템)를 붙이는 자리이고, 저장 공간은 위쪽 「스토리지 구성」에서 이미 정했다. 둘을 혼동하기 쉽다.

| | 무엇인가 | 이 프로젝트 |
|---|---|---|
| 스토리지 구성 | EBS — 인스턴스에 붙는 블록 디스크 | **gp3 20 GiB** |
| 파일 시스템 | EFS — 여러 인스턴스가 공유하는 NFS | **사용 안 함** |

인스턴스가 하나라 공유할 대상이 없고, 더 중요하게는 **PostgreSQL 데이터를 NFS에 두면 안 된다** — 파일 잠금과 `fsync` 동작이 로컬 디스크와 달라 손상 위험이 있다. DB 데이터는 Docker 볼륨을 통해 EBS에 남는다. EFS는 별도 과금이기도 하다.

**ED25519를 고르는 이유.** 타원곡선 기반이라 256비트 키로 RSA 2048비트보다 높은 보안 강도를 내고 서명도 빠르다. macOS와 Amazon Linux 2023 모두 지원하므로 호환성 문제가 없다. RSA가 필요한 경우는 아주 오래된 클라이언트나 Windows 인스턴스이고, 둘 다 해당하지 않는다.

**`.pem`을 고르는 이유.** OpenSSH 형식이라 터미널의 `ssh` 명령이 그대로 쓴다. `.ppk`는 Windows의 PuTTY 전용이다.

받은 즉시 옮기고 권한을 고친다. **권한을 안 고치면 SSH가 거부한다** — 남이 읽을 수 있는 파일은 개인키로 인정되지 않는다.

```bash
mv ~/Downloads/loan-demo.pem ~/.ssh/ && chmod 400 ~/.ssh/loan-demo.pem
```

**확인:** 인스턴스 상태가 `실행 중`, 상태 검사 2/2 통과.

## 2. 탄력적 IP 할당·연결

`EC2 → 네트워크 및 보안 → 탄력적 IP → 탄력적 IP 주소 할당` → 생성 후 `작업 → 탄력적 IP 주소 연결` → 인스턴스 선택

**왜 필요한가.** 기본 공인 IP는 인스턴스를 껐다 켜면 **바뀐다.** 바뀌면 DNS를 매번 고쳐야 하고, 그 사이 도메인이 죽은 곳을 가리킨다.

**확인:** 탄력적 IP가 인스턴스에 연결됨. 이 주소를 적어 둔다 — §4에서 쓴다.

> 탄력적 IP는 **인스턴스에 연결돼 있어도 과금된다**(시간당 약 $0.005, 월 $3.6). 연결하지 않고 놀리면 더 비싸다. 쓰지 않게 되면 **반드시 해제(release)** 한다.

## 3. 보안 그룹 — 인바운드 규칙

`EC2 → 보안 그룹 → 해당 그룹 → 인바운드 규칙 편집`

| 유형 | 포트 | 소스 | 이유 |
|---|---|---|---|
| HTTP | 80 | `0.0.0.0/0` | Let's Encrypt 발급 확인 + HTTPS 리다이렉트 |
| HTTPS | 443 | `0.0.0.0/0` | 실제 서비스 |
| SSH | 22 | **내 IP** | 관리. 전체 공개하지 않는다 |

**8501·8000·5432는 열지 않는다.** Caddy가 유일한 진입점이고 나머지는 컨테이너 내부망에만 있다. 이것이 ADR-011의 3-tier 격리가 실환경에서 증명되는 지점이다.

**확인:** 인바운드 규칙이 정확히 3개.

## 4. Cloudflare DNS — A 레코드

`Cloudflare 대시보드 → gwang.dev → DNS → 레코드 추가`

| 항목 | 값 |
|---|---|
| 유형 | **A** |
| 이름 | `loan` |
| IPv4 주소 | §2에서 적어 둔 탄력적 IP |
| 프록시 상태 | **회색 구름 (DNS only)** ← 반드시 |
| TTL | 자동 |

**주황색 구름이면 안 된다.** Cloudflare가 TLS를 종료해서 **EC2까지는 평문**이 되고, 방문자의 OpenAI 키가 그 구간을 평문으로 지난다(ADR-031 §31.5·§31.6-c). CloudFront를 기각한 이유가 그대로 재현된다.

**확인 — 전파될 때까지 기다린다.**

```bash
dig +short loan.gwang.dev
```

탄력적 IP가 나와야 한다. 수 분 걸릴 수 있다. **여기서 IP가 안 나오면 §5로 가지 않는다** — Caddy가 인증서를 못 받는다.

## 5. 서버 준비 — Docker 설치



**그룹 변경을 적용하려면 다시 접속해야 한다.** 나갔다 들어온다.

```bash

```

**확인:**

```bash
docker compose version && docker run --rm hello-world
```

### 5.1 스왑 — 빌드 중 메모리 부족 방지

`t4g.small`은 메모리 2 GiB다. 의존성 설치 중 부족해질 수 있고, 그러면 빌드가 조용히 죽는다. **먼저 만들어 두면 겪지 않는다.**

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 status=none
sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

**확인:** `free -h`에 Swap 2.0Gi.

## 6. 코드와 설정

```bash
git clone -b feature/decision-support-rebuild https://github.com/Gwangdev/loan-suitability-agent.git
cd loan-suitability-agent
```

`.env`를 만든다. **서버 OpenAI 키는 넣지 않는다** — 방문자가 자기 키를 쓰고, 운영에 서버 키를 두지 않는 것이 ADR-031 §31.3이다.

```bash
cat > .env << 'EOF'
POSTGRES_USER=loan
POSTGRES_PASSWORD=여기에_긴_임의_문자열
POSTGRES_DB=loan_suitability
EOF
chmod 600 .env
```

비밀번호는 직접 짓지 말고 만들어 쓴다.

```bash
openssl rand -base64 24
```

**확인:** `.env`에 세 줄, `OPENAI_API_KEY`가 **없어야** 한다.

## 7. 기동

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

**`--profile local`을 붙이지 않는다.** 붙이면 워커가 뜨고, 워커는 서버 키가 없어 할 일이 없으면서 **방문자가 집으려던 `PENDING` 행을 먼저 집어 실패시킨다**(§31.3).

빌드는 5~10분 걸린다.

**확인:**

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
```

`caddy`·`ui`·`app`·`postgres` 넷이 `healthy`, `migrate`는 `Exited (0)`이면 정상이다.

인증서 발급 로그를 본다.

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs caddy | grep -i certificate
```

## 8. 동작 확인

```bash
curl -I https://loan.gwang.dev
```

`HTTP/2 200`이어야 한다.

```bash
curl -sI http://loan.gwang.dev | head -1
```

`301`·`308`로 HTTPS 리다이렉트되어야 한다.

브라우저로 열어 **셋을 확인한다.**

1. **자물쇠 표시** — 인증서가 유효한가
2. **「토큰 없이 데모 보기」** — 녹화본이 뜨고, 「판정 근거 원문 보기」에 규칙의 산출물이 나오는가
3. **본인 키로 안내문 생성** — 방문자 키 경로가 실제로 도는가

**8000·8501이 막혔는지도 확인한다.**

```bash
curl -m 5 http://loan.gwang.dev:8000/health/ready ; echo "  ↑ 실패해야 정상"
```

## 9. 막히는 지점

| 증상 | 원인과 조치 |
|---|---|
| Caddy가 인증서를 못 받음 | ①DNS 전파 미완 — `dig`로 확인 ②80이 막힘 — 보안 그룹 ③**Cloudflare 주황색 구름** — 회색으로 |
| `app`이 계속 unhealthy | `migrate`가 실패했을 가능성. `logs migrate` 확인. `.env`에 `POSTGRES_USER`·`POSTGRES_PASSWORD`가 있는가 |
| 빌드가 중간에 죽음 | 메모리 부족. §5.1 스왑을 만들었는가 |
| SSH 거부 | `chmod 400` 했는가. 보안 그룹의 「내 IP」가 바뀌었을 수 있다. 키 유형이 ED25519면 클라이언트가 OpenSSH 6.5+ 여야 한다(macOS 기본은 충족) |
| 화면은 뜨는데 심사가 안 됨 | `ui`가 `app`을 못 부르는 것. `logs ui` 확인 |

## 10. 비용 관리

**제출·면접이 끝나면 인스턴스를 정지한다.**

```
EC2 → 인스턴스 → 인스턴스 상태 → 인스턴스 중지
```

정지 중에는 EBS와 탄력적 IP 요금만 나간다(월 $5 수준). **완전히 끝나면 탄력적 IP를 해제하고 인스턴스를 종료(terminate)** 한다 — 연결되지 않은 탄력적 IP는 더 비싸다.

**Budget 알림을 걸어 두었는지 확인한다.** `Billing → Budgets`, 월 $20, 80%에서 이메일.
