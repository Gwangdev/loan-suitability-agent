# 배포 계획

**작성 2026-08-31 · 근거 ADR-031 · 미결: 도메인 선택**

> 이 문서는 **선택을 위한 자료**다. 결정은 「도메인을 살 것인가」 하나이고, 나머지는 그 답에 따라 정해진다.

---

## 1. 무엇을 배포하는가

지금 로컬에서 도는 것은 컨테이너 넷이다.

| 서비스 | 하는 일 | 포트 |
|---|---|---|
| `ui` | Streamlit 화면 | 8501 |
| `app` | FastAPI — 심사·판정·설명 실행 | 8000 |
| `worker` | 설명 실행기 (비동기 아웃박스 소비자) | 없음 |
| `postgres` | 데이터 | 5432 (컨테이너 내부 전용) |

**운영에는 셋만 올린다.** `worker`와 서버 OpenAI 키는 제외한다(ADR-031 §31.3).

- **서버 키 제외** — 방문자가 자기 키를 쓰므로 사용자 지갑이 열리지 않는다
- **워커 제외** — 키가 없어 할 일이 없고, 켜 두면 방문자가 집으려던 `PENDING` 행을 먼저 집어 실패시킨다

**대가:** 공개 데모에서는 비동기 경로가 동작하지 않는다. 이 사실을 README에 적어야 한다. 비동기 아웃박스는 로컬 compose와 영상 데모에서 보여준다.

---

## 2. 개념 정리 — 도메인·DNS·TLS가 각각 무엇인가

배포에서 헷갈리는 지점이 여기라 먼저 정리한다.

### 2.1 IP 주소와 도메인

EC2를 켜면 `13.125.xxx.xxx` 같은 **공인 IP**가 붙는다. 이것만으로도 접속은 된다.

```
http://13.125.xxx.xxx:8501
```

**도메인은 그 숫자에 붙이는 이름표다.** `loan.example.com` → `13.125.xxx.xxx`로 가라는 안내를 DNS가 한다.

도메인이 하는 일은 둘이다.

1. **사람이 기억할 수 있게 한다** — 포트폴리오 링크가 IP면 인상이 나쁘다
2. **인증서를 받을 수 있게 한다** ← **이게 진짜 이유다**

### 2.2 DNS 레코드

도메인을 사면 「어느 IP로 보낼지」를 등록해야 한다. 필요한 것은 한 종류뿐이다.

| 종류 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| **A 레코드** | 도메인 → IPv4 주소 | `loan.내도메인.com` → EC2 공인 IP |

등록하면 전 세계 DNS에 퍼지는 데 **수 분~수 시간**이 걸린다(TTL). 그래서 도메인은 **일찍** 정하는 게 좋다.

### 2.3 TLS 인증서 — 왜 IP로는 못 받는가

HTTPS를 쓰려면 **인증서**가 필요하고, 인증서는 「이 이름의 주인이 맞다」를 증명하는 물건이다. 발급 기관(Let's Encrypt 등)은 **도메인 소유를 확인**해서 발급한다 — 확인 방법이 「그 도메인으로 접속했을 때 네가 응답하는가」이므로, **이름이 없으면 증명할 대상도 없다.**

> 공인 IP에 대한 인증서는 원칙적으로 발급되지 않는다. 그래서 도메인이 필요하다.

### 2.4 왜 이 프로젝트에 TLS가 필수인가

일반적인 「HTTPS가 좋다」 수준이 아니다. **방문자의 OpenAI API 키가 HTTP 헤더로 서버에 온다**(ADR-024 §24-R).

```
POST /api/v1/assessments/{id}/explanation-runs
X-OpenAI-API-Key: sk-proj-....
```

평문 HTTP면 이 키가 네트워크를 그대로 지난다. 리스크 대장 A4가 「키는 세션 메모리에만 둔다」고 적은 통제가 **전송 구간에서 무의미해진다.** 그래서 ADR-031 §31.5가 **TLS가 없으면 방문자 키 기능 자체를 켜지 않는다**고 정했다.

## 3. 선택지 4가지

| | TLS 방식 | §31.5 충족 | ADR-031 유지 | 비용 | 시간 |
|---|---|---|---|---|---|
| **① 도메인 + Caddy** | Let's Encrypt 자동 | **완전** | **유지** | ~15,000원/년 | 30분 |
| ② CloudFront + EC2 | AWS 기본 인증서 | **부분** | 유지 | 사실상 0 | 2~3시간 |
| ③ PaaS | 제공 서브도메인 | 완전 | **뒤집힘** | 0~ | 1~2시간 |
| ④ 라이브 포기 | — | 해당 없음 | — | 0 | — |

### ① 도메인 구입 + Caddy — 권고

**Caddy**는 리버스 프록시인데, 도메인만 적어 주면 **Let's Encrypt에서 인증서를 자동으로 받아오고 만료 전에 자동으로 갱신한다.** 설정이 이 정도다.

```
loan.내도메인.com {
    reverse_proxy ui:8501
}
```

이 세 줄이면 `https://loan.내도메인.com`이 동작한다. 인증서 발급·갱신·HTTP→HTTPS 리다이렉트가 전부 자동이다.

**구입처**

| 곳 | 특징 |
|---|---|
| [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/) | **원가 판매**(마진 0). `.com` 연 $10 내외. 가장 쌈 |
| 가비아·후이즈 | 국내 결제·한글 지원. 첫 해 할인이 있으나 갱신가가 비쌀 수 있음 |
| Namecheap·Porkbun | 중간. 관리 화면이 편함 |

**TLD 고르기**

- `.com` — 무난. 연 $10~15
- `.dev` · `.app` — **HSTS가 기본 강제**라 HTTP 접속이 원천 차단된다. 이 프로젝트 취지에 맞고 개발자 포트폴리오로 자연스럽다. 연 $12~20
- `.xyz` · `.me` · `.site` — 더 쌈. 첫 해 $1~3짜리도 있으나 **갱신가를 확인할 것**

> **이건 재사용 자산이다.** SK AX·타 금융권에도 지원하실 것이고, 본인 도메인은 이력서·GitHub README·포트폴리오에 계속 쓴다. 1년치가 커피 두 잔 값이다.

### ② CloudFront + EC2 — 도메인 없이 AWS 유지

CloudFront 배포를 만들면 `d111111abcdef8.cloudfront.net` 주소와 **AWS 관리 인증서가 무료로 붙는다.** 도메인 없이 HTTPS를 얻는다.

**한계가 결정적이다.** CloudFront가 감싸는 것은 **뷰어 구간**(브라우저 ↔ CloudFront)뿐이고, **CloudFront ↔ EC2 원본 구간은 평문 HTTP**가 된다. 원본을 HTTPS로 하려면 EC2에 신뢰받는 인증서가 있어야 하는데 그러려면 다시 도메인이 필요하다 — **순환이다.**

보완책은 있다. 보안그룹을 CloudFront 관리 프리픽스 리스트로 제한하고 비밀 헤더를 붙여 원본을 CloudFront에서만 닿게 만든다. **그래도 그 구간이 평문인 사실은 변하지 않는다.**

**이 길을 택하면 §31.5를 「뷰어 구간만 TLS」로 개정하고 한계를 README에 적어야 한다.** 정직하게 적으면 답이 되지만, *「방문자 키가 평문 구간을 지납니다」*는 포트폴리오에서 설명하기 껄끄러운 문장이다.

### ③ PaaS (Render · Railway · Fly.io)

제공 서브도메인(`*.onrender.com` 등)과 TLS가 함께 온다. 도메인 불필요, TLS 완전.

**대가는 ADR-031을 뒤집는 것이다.** 「한화생명이 AWS를 쓰고 국내 금융권 53%가 AWS」가 그 결정의 근거였다. 뒤집으려면 `/design` §5를 경유해 ADR을 개정해야 하고, 면접에서 「왜 AWS라고 해 놓고 안 썼나」에 답할 거리가 필요하다.

### ④ 라이브 포기 → 영상 데모

ADR-031 §31.4의 중단 기준이다. **9월 6일까지 배포가 안정화되지 않으면 자동으로 이 길이다.** 새 판단이 아니라 이미 적어 둔 안전망이다.

### 기각한 것 — `nip.io` · `sslip.io`

`13.125.1.1.nip.io`처럼 IP를 이름으로 바꿔 주는 무료 서비스다. 언뜻 ①의 공짜 버전 같지만 **쓸 수 없다.**

두 도메인이 Public Suffix List에 등재되지 않아 **모든 하위 도메인이 하나의 Let's Encrypt 레이트리밋을 공유한다.** 남들이 소진하면 내 인증서가 발급되지 않고, 실제로 그 실패가 여러 차례 보고돼 있다. **제출 마감을 앞두고 타인의 사용량에 배포가 걸리는 구조는 채택하지 않는다.**

## 4. ① 을 택했을 때의 실제 절차

### 4.1 EC2 인스턴스

| 항목 | 값 | 근거 |
|---|---|---|
| 타입 | `t4g.small` (ARM, 2 vCPU / 2 GiB) | 컨테이너 3개 + 빌드를 감당하는 최소. ARM이 같은 성능에 더 쌈 |
| 대안 | `t3.small` (x86) | ARM 이미지 빌드가 번거로우면 |
| 스토리지 | gp3 20 GiB | 이미지·DB·로그 |
| 리전 | `ap-northeast-2` (서울) | 지연시간 |
| OS | Amazon Linux 2023 또는 Ubuntu 24.04 | Docker 설치 편의 |

**비용:** `t4g.small` 온디맨드 기준 월 $12 내외 + 스토리지 약 $2. **프리티어 대상 계정이면 `t2.micro`/`t3.micro`가 12개월 무료지만 메모리 1 GiB라 빌드가 버겁다** — 빌드는 로컬에서 하고 이미지만 올리는 방법으로 우회 가능하다.

> **제출이 끝나면 인스턴스를 정지한다.** 정지 중에는 스토리지 요금만 나간다.

### 4.2 보안그룹 (인바운드)

| 포트 | 소스 | 왜 |
|---|---|---|
| 80 | 0.0.0.0/0 | Let's Encrypt 발급 확인 + HTTPS 리다이렉트 |
| 443 | 0.0.0.0/0 | 실제 서비스 |
| 22 | **본인 IP만** | SSH. 필요할 때만 열고 주소를 한정 |

**8000·8501·5432는 열지 않는다.** Caddy가 유일한 진입점이 되고, 나머지는 컨테이너 내부망에서만 닿는다. 이것이 ADR-011의 3-tier 격리가 실환경에서 증명되는 지점이고, 대장 B3가 「실서비스라면 진입점을 리버스 프록시 하나로 모은다」고 적어 둔 것이 여기서 실현된다.

### 4.3 compose 변경

지금 `app`이 호스트 8000, `ui`가 호스트 8501을 게시하고 있다. **둘 다 제거하고 `caddy`만 80·443을 연다.**

```
caddy (80/443)  →  ui:8501  →  app:8000  →  postgres:5432
   ↑ 유일한 진입점        └── frontend망 ──┘   └─ backend망 ─┘
```

### 4.4 순서

1. 도메인 구입
2. EC2 기동 → 공인 IP 확보 (**탄력적 IP를 붙일 것** — 재시작 시 IP가 바뀌면 DNS를 다시 고쳐야 한다)
3. DNS **A 레코드** 등록: `loan.내도메인.com` → 그 IP
4. 전파 확인 (`dig loan.내도메인.com`)
5. EC2에 Docker·compose 설치, 저장소 클론
6. `.env` 작성 (**`POSTGRES_USER`·`POSTGRES_PASSWORD` 필수.** 서버 OpenAI 키는 넣지 않는다)
7. `docker compose up -d --build`
8. Caddy가 인증서를 받는지 로그 확인
9. `https://loan.내도메인.com` 접속 → 방문자 키로 안내문 생성까지 확인

**3~4를 먼저 해 두면 좋다.** DNS 전파가 가장 오래 걸리는 단계다.

## 5. 결정이 필요한 것

**도메인을 살 것인가.**

- **산다** → ① 로 간다. `Caddyfile` 작성, compose 수정, EC2 절차 스크립트를 준비하겠다
- **안 산다** → ② 로 가되 §31.5를 개정하고 한계를 문서에 명시한다
- **어느 쪽도 9/6까지 안 되면** → ④ 가 자동 적용된다(§31.4)

**오늘이 8월 31일이다.** DNS 전파에 시간이 걸리므로 일찍 정할수록 여유가 생긴다.
